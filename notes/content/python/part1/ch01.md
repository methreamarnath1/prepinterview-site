# Chapter 1 — Introduction & Python's Execution Model

## 1.1 What is Python?

### Definition
> Python is a high-level, general-purpose programming language that focuses on code readability and lets developers write programs using fewer lines of code than most other languages.

### Easy Meaning
Python is a programming language that is easy to read and write, almost like plain English.

### Remember It
**Python = simple syntax + readable code + does a lot with less code.**

### Why is it used?
Python is used because it is easy to learn, has a huge collection of ready-made libraries, and can be used for many purposes — web development, data science, automation, AI, and scripting. Companies use it because developers can build things faster with it.

### How it works (high-level)
1. You write Python code in a `.py` file.
2. Python converts your code into an internal format called bytecode.
3. A program called the Python Virtual Machine runs that bytecode line by line.
4. You see the output on the screen.

(The exact mechanism is explained in detail in section 1.6.)

### Interview Question
**Q: What is Python, and why is it popular?**

### Short Interview Answer
"Python is a high-level, general-purpose programming language known for its simple and readable syntax. It's popular because it's easy to learn, has a large standard library, and is widely used in web development, data science, automation, and AI."

### Detailed Explanation
Python was designed with readability as a priority, so its syntax looks close to plain English compared to languages like Java or C++. It is dynamically typed, meaning you don't have to declare variable types. It also has an enormous ecosystem of third-party libraries (like NumPy, Django, Pandas), which is a major reason it's used so widely in different industries.

### How I Would Answer in an Interview
"Python is a programming language that's popular because it's easy to write and understand. I like it because I can focus on solving the problem instead of writing a lot of boilerplate code. It's used in a lot of different fields — I've mainly used it for [scripting/web development/data analysis], but it's also big in AI and automation."

### Follow-up Questions
1. Who created Python? — **Guido van Rossum, first released in 1991.**
2. Is Python compiled or interpreted? — **Both — covered fully in section 1.6.**
3. What are some real-world uses of Python? — **Web backends (Django/Flask), data science (Pandas/NumPy), automation scripts, AI/ML (TensorFlow/PyTorch).**

### Quick Revision
- Definition: High-level, readable, general-purpose language.
- Key points: Created by Guido van Rossum, 1991; dynamically typed; huge library ecosystem.
- Interview answer: readable + easy to learn + huge library support.
- Remember: **Python = simple syntax + readable code + does a lot with less code.**

## 1.2 Python Implementations (CPython, PyPy, etc.)

### Definition
> A Python implementation is the actual software that runs Python code. Python itself is just a set of rules (a specification); an implementation is the program that follows those rules.

### Easy Meaning
Python is like a recipe. CPython, PyPy, and others are different "chefs" who can cook that recipe. The final dish (your program's behavior) should mostly taste the same, but each chef may work a little differently behind the scenes.

### Remember It
**Python = the rules. CPython = the most common chef who follows those rules.**

### Why is it used?
Different implementations exist for different needs — CPython is the standard, most widely used version. PyPy runs code faster for long programs because it compiles code as it runs (JIT). Jython lets Python talk to Java code. IronPython lets Python talk to .NET code.

### Important Differences

| Implementation | Written In | Best For |
|---|---|---|
| CPython | C | Default choice; most libraries support it |
| PyPy | RPython | Long-running programs needing speed |
| Jython | Java | Working inside a Java environment |
| IronPython | C# | Working inside a .NET environment |

### Interview Question
**Q: What is CPython, and how is it different from Python?**

### Short Interview Answer
"Python is the language specification — the set of rules for how the language should behave. CPython is the most common implementation of those rules, written in C. When people say 'Python,' they usually mean CPython, since it's the default and most widely used version."

### Detailed Explanation
There can be more than one program that correctly implements the Python language. CPython is the reference implementation maintained by the Python core team, and it's what you get when you download Python from python.org. Other implementations like PyPy exist to optimize for speed using Just-In-Time compilation, while Jython and IronPython let Python interact directly with Java and .NET ecosystems.

### Common Interview Trap
**Wrong thinking:** "Reference counting and small integer caching are guaranteed by the Python language."
**Correct thinking:** These are CPython-specific implementation choices, not guarantees of the Python language itself. Other implementations (like PyPy) may behave differently.
**What to say in the interview:** "That behavior is specific to CPython — it's not something the Python language spec guarantees, so it shouldn't be relied on for correctness."

### Quick Revision
- Definition: Implementation = the actual program that runs Python's rules.
- Key point: CPython is the default; others exist for different needs (speed, Java/.NET integration).
- Remember: **Python = the rules. CPython = the most common chef.**

## 1.3 Python's Execution Model — Bytecode & the PVM

### Definition
> Python source code is first compiled into an intermediate form called bytecode, and then that bytecode is executed, one instruction at a time, by the Python Virtual Machine (PVM).

### Easy Meaning
Before Python runs your code, it quietly translates it into a simpler internal language (bytecode). Then a built-in "engine" (the PVM) reads that internal language and actually performs the actions.

### Remember It
**Source code → Bytecode (compiled) → PVM (interpreted) → Output.**

### Why is it used?
This two-step process makes Python portable — the same bytecode can run on any machine that has a PVM, without needing to recompile the original source for each machine's hardware.

### How it works
1. Python parses your `.py` file into an internal structure.
2. It compiles that structure into bytecode instructions (you can see these using the `dis` module).
3. Bytecode is cached in `.pyc` files inside a `__pycache__` folder, so Python doesn't recompile unchanged files every time.
4. The PVM reads and executes the bytecode instructions one by one, using an internal stack to perform operations.

### Syntax / Example
```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
```
Output (illustrative):
```
LOAD_FAST   a
LOAD_FAST   b
BINARY_OP   +
RETURN_VALUE
```

### Common Mistakes
- Saying "Python is only interpreted" — technically incomplete, since bytecode compilation happens first.
- Saying "Python is compiled" without qualification — misleading, since it's not compiled to native machine code like C.

### Interview Question
**Q: Is Python interpreted or compiled?**

### Short Interview Answer
"Python is both. Python source code is compiled into bytecode first, and then that bytecode is interpreted and executed by the Python Virtual Machine. So it's not purely interpreted, and it's not compiled to machine code the way C is."

### Detailed Explanation
When you run a `.py` file, CPython compiles it into bytecode — a lower-level, platform-independent set of instructions. This bytecode is cached in `.pyc` files. Then, the PVM reads this bytecode and executes it instruction by instruction using a stack-based virtual machine. This is different from compiled languages like C, where source code is translated directly into machine code that the CPU executes natively.

### How I Would Answer in an Interview
"It's actually both — Python compiles your code into bytecode first, and then a virtual machine inside Python runs that bytecode. So there is a compilation step, but it doesn't compile all the way down to machine code like C does — that's why people call it an interpreted language, even though that's a bit of a simplification."

### Follow-up Questions
1. What tool can you use to see Python's bytecode? — **The `dis` module.**
2. Where is compiled bytecode cached? — **In `__pycache__`, as `.pyc` files.**
3. Does every implementation of Python use bytecode the same way? — **No — this is CPython's approach; other implementations like PyPy may compile differently (e.g., JIT to machine code).**

### Interview Depth Levels
**Basic:** What does "interpreted language" mean?
**Intermediate:** What is the PVM, and what does it do?
**Tricky:** If PyPy uses JIT compilation to machine code, is it still accurate to call "Python" an interpreted language?
*(Tricky answer: It depends on the implementation — CPython uses bytecode + a virtual machine, while PyPy's JIT compiles hot code paths to machine code at runtime. The language itself doesn't mandate either approach — this is implementation-specific.)*

### Quick Revision
- Definition: Source → bytecode (compiled) → PVM (interpreted).
- Key point: Not purely interpreted, not compiled to machine code.
- Interview answer: "Both — compiled to bytecode, then interpreted by the PVM."
- Remember: **Source code → Bytecode → PVM → Output.**

## 1.4 Python Version History (Reference Table)

### Easy Meaning
A quick timeline of major Python versions and what changed, useful for interview small-talk and understanding why certain code looks different across versions.

| Version | Year | Key Change |
|---|---|---|
| 0.9.0 | 1991 | First public release |
| 2.0 | 2000 | List comprehensions, garbage collector |
| 3.0 | 2008 | Breaking change; `print()` as function, unified string handling |
| 3.5 | 2015 | `async`/`await` |
| 3.6 | 2016 | f-strings |
| 3.7 | 2018 | `dataclasses`; dict order became a guarantee |
| 3.8 | 2019 | Walrus operator `:=`, positional-only params |
| 3.9 | 2020 | Dict merge operators `|`, `|=` |
| 3.10 | 2021 | `match`/`case` pattern matching |
| 3.11+ | 2022+ | Performance improvements, better error messages |

### Interview Question
**Q: Why isn't Python 2 code compatible with Python 3?**

### Short Interview Answer
"Python 3 introduced breaking changes to fix core design issues — like separating `str` and `bytes` properly, making `print` a function instead of a statement, and changing integer division behavior. These changes improved the language but broke backward compatibility with Python 2."
