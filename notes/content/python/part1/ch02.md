## 2.1 The REPL and Running Scripts

### Definition
> The REPL (Read-Eval-Print Loop) is Python's interactive mode, where you type one line of code at a time and see the result immediately.

### Easy Meaning
It's like a chat window where you type Python code and it replies instantly with the answer.

### Remember It
**REPL = type code, see result, instantly.**

### Why is it used?
Developers use the REPL to quickly test small pieces of code, check syntax, or explore a new library without writing a full script.

### Syntax / Example
```bash
$ python3
>>> 2 + 2
4
>>> print("hello")
hello
```

### Important Differences

| Aspect | REPL | Script (`python3 file.py`) |
|---|---|---|
| Execution | One line at a time, immediate result | Whole file at once |
| Use case | Quick testing/exploration | Real programs |
| Persistence | Nothing saved after closing | Saved in a `.py` file |

### Interview Question
**Q: What is the Python REPL, and when would you use it?**

### Short Interview Answer
"The REPL is Python's interactive shell — it lets you type code line by line and see results immediately. I use it to quickly test small snippets or check how a function behaves, without writing a full script."

## 2.2 Virtual Environments

### Definition
> A virtual environment is an isolated Python setup that has its own separate set of installed packages, so different projects don't interfere with each other's dependencies.

### Easy Meaning
It's like giving each project its own private toolbox, so tools (packages) from one project don't mix up with another project's tools.

### Remember It
**Virtual environment = one clean, isolated toolbox per project.**

### Why is it used?
Different projects often need different versions of the same library. Without isolation, installing one version for Project A could break Project B, which needs a different version. Virtual environments prevent this conflict.

### How it works
1. You create a virtual environment folder using `venv`.
2. That folder gets its own copy/link of the Python interpreter and an empty `site-packages` directory.
3. When you "activate" it, your terminal starts using that isolated Python and its packages instead of the system-wide one.
4. Any package you install while activated goes only into that environment.

### Syntax
```bash
python3 -m venv myenv
source myenv/bin/activate      # Linux/Mac
myenv\Scripts\activate         # Windows
pip install requests
deactivate
```

### Common Mistakes
- Installing packages globally instead of inside a venv, causing version conflicts across projects.
- Forgetting to activate the venv before installing packages.
- Committing the venv folder itself to version control instead of just `requirements.txt`.

### Interview Question
**Q: Why do we use virtual environments in Python?**

### Short Interview Answer
"A virtual environment isolates a project's dependencies from other projects and from the system Python. This avoids version conflicts — for example, if two projects need different versions of the same library, each can have its own environment without clashing."

### Detailed Explanation
When you activate a virtual environment, your terminal's `PATH` is updated so that `python` and `pip` point to the environment's own copies instead of the system-wide installation. Any packages you install go into that environment's private `site-packages` folder. This means you can safely experiment, upgrade, or downgrade packages for one project without affecting any other project or the operating system's Python installation.

### Follow-up Questions
1. What command creates a virtual environment? — **`python3 -m venv <name>`.**
2. How do you share your project's dependencies with someone else? — **Generate a `requirements.txt` with `pip freeze > requirements.txt`, and they run `pip install -r requirements.txt`.**

### Quick Revision
- Definition: Isolated Python setup per project.
- Key point: Prevents dependency version conflicts.
- Remember: **Virtual environment = one clean, isolated toolbox per project.**

## 2.3 PEP 8 — The Style Guide

### Definition
> PEP 8 is Python's official style guide — a set of recommended conventions for formatting and writing readable Python code.

### Easy Meaning
It's the "rulebook" for making Python code look clean and consistent so any Python developer can read it easily.

### Remember It
**PEP 8 = Python's official handwriting rules.**

### Why is it used?
Consistent formatting makes code easier to read, review, and maintain — especially in teams. Many companies enforce PEP 8 through automated linters.

### Key Rules
- 4 spaces per indent level (no tabs).
- `snake_case` for variables/functions, `PascalCase` for classes, `UPPER_CASE` for constants.
- Two blank lines between top-level functions/classes.
- Imports at the top, grouped: standard library → third-party → local.

### Interview Question
**Q: What is PEP 8?**

### Short Interview Answer
"PEP 8 is Python's official style guide. It defines conventions like using 4 spaces for indentation, snake_case for variable names, and consistent spacing, so that Python code stays readable and consistent across different developers and teams."
