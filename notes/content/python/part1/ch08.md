# Chapter 8 — Strings & Text

## 8.1 String Immutability, Unicode, Encoding/Decoding

### Definition
> Python `str` objects are immutable sequences of Unicode code points. Encoding converts a `str` into `bytes` using a specific scheme (like UTF-8); decoding converts `bytes` back into a `str`.

### Easy Meaning
Text (`str`) is what humans read. Bytes are what computers store/transmit. Encoding = str → bytes. Decoding = bytes → str.

### Remember It
**Encode: text → bytes. Decode: bytes → text.**

### Simple Example
```python
s = "café"
b = s.encode("utf-8")
print(b)              # b'caf\xc3\xa9'
s2 = b.decode("utf-8")
print(s2)               # 'café'
```

### Common Mistakes
- Trying to concatenate `str` and `bytes` directly — raises `TypeError`.
- Mixing up which encoding was used to write a file versus which is used to read it.

### Interview Question
**Q: What's the difference between `str` and `bytes` in Python 3?**

### Short Interview Answer
"`str` represents human-readable text as Unicode code points, while `bytes` represents raw binary data. To go from text to bytes, we encode using something like UTF-8; to go from bytes back to text, we decode. They're separate types in Python 3 and can't be mixed directly."

### Detailed Explanation
In Python 2, `str` actually meant bytes, which caused a lot of confusion when working with non-ASCII text. Python 3 fixed this by making `str` always represent Unicode text, and introducing a distinct `bytes` type for raw binary data. This is why file handling in Python 3 has both text mode and binary mode — text mode automatically encodes/decodes for you, while binary mode gives you raw bytes.

## 8.2 String Concatenation Performance

### Definition
> Because strings are immutable, using `+=` repeatedly inside a loop creates a brand-new string object every time, which is inefficient for large amounts of text. Using `"".join(list_of_pieces)` is the efficient alternative.

### Easy Meaning
Don't glue strings together one at a time in a loop — collect the pieces in a list and glue them all at once with `join`.

### Remember It
**Loop + `+=` on strings = slow. `"".join(list)` = fast.**

### Interview Question
**Q: Why is `"".join()` preferred over `+=` for building a large string in a loop?**

### Short Interview Answer
"Strings are immutable, so every `+=` in a loop creates a brand-new string object, copying everything each time — this becomes slow as the string grows. `.join()` builds the final string in one efficient pass instead, so it's the recommended approach for large or looped string building."
