# Chapter 9 — Core Collections: Lists, Tuples, Sets, Dictionaries

## 9.1 Lists

### Definition
> A list is a built-in, ordered, mutable collection that can hold values of different types, and allows duplicates.

### Easy Meaning
A list is a flexible container where you can add, remove, or change items whenever you want, and the order you put things in is remembered.

### Remember It
**List = ordered + mutable + duplicates allowed.**

### Why is it used?
Lists are used any time you need a collection of items that might grow, shrink, or change over the life of a program — like a shopping cart, a queue of tasks, or collected results.

### Syntax / Simple Example
```python
numbers = [10, 20, 30]
numbers.append(40)
numbers[0] = 99
print(numbers)   # [99, 20, 30, 40]
```

### Realistic Example
```python
scores = []
for _ in range(3):
    scores.append(int(input("Enter score: ")))
print("Average:", sum(scores) / len(scores))
```

### Important Differences

| Method | What it does | Complexity | Notes |
|---|---|---|---|
| `append(x)` | Add to end | O(1) amortized | Most common way to add |
| `insert(i, x)` | Add at index | O(n) | Shifts elements |
| `pop()` | Remove & return last | O(1) | |
| `pop(i)` | Remove & return at index | O(n) | |
| `remove(x)` | Remove first matching **value** | O(n) | Raises `ValueError` if not found |
| `del lst[i]` | Delete by index (no return) | O(n) | |

### Common Interview Trap
**Wrong thinking:** "`lst.sort()` returns the sorted list."
**Correct thinking:** `sort()` mutates the list in place and returns `None`. Use `sorted(lst)` if you want a new sorted list returned.
**What to say in the interview:** "I'd point out that `list.sort()` sorts in place and returns `None`, so assigning its result would silently give you `None` — that's a classic bug. `sorted()` is the function to use when you need a new list back."

### Interview Question
**Q: What is a list in Python?**

### Short Interview Answer
"A list is a built-in Python data structure used to store multiple values in an ordered collection. It's mutable, so we can add, remove, or change elements after creating it. Lists can also contain different types of values."

### How I Would Answer in an Interview
"A list is basically Python's go-to way of storing a bunch of related things in order — like `[10, 20, 30]`. It's mutable, so I can add or remove items later with things like `append` or `pop`. It also allows duplicates and mixed types, which makes it very flexible."

### Follow-up Questions
1. Is a list mutable? — **Yes.**
2. Can a list contain duplicate values? — **Yes.**
3. How is a list different from a tuple? — **See section 9.2's comparison table.**
4. What's the time complexity of accessing a list element by index? — **O(1) — lists are backed by a contiguous array internally.**
5. What's the time complexity of `in` on a list? — **O(n) — it checks elements one by one.**

### Predict the Output
```python
matrix = [[0] * 3] * 3
matrix[0][0] = 1
print(matrix)
```
**Answer:** `[[1, 0, 0], [1, 0, 0], [1, 0, 0]]`
**Explanation:** `[[0]*3]*3` creates one inner list and then repeats *the same reference* to it three times — it does not create three independent lists. Mutating one "row" mutates all of them, because they're all the same object.
**Interview Concept Tested:** Deep understanding of reference-sharing, not just surface-level list syntax.

### Coding Practice
**Beginner:** Write code to remove duplicates from a list while preserving order.
**Intermediate:** Fix the `[[0]*3]*3` bug so each row is an independent list.
**Solution (Intermediate):**
```python
matrix = [[0]*3 for _ in range(3)]   # list comprehension creates a NEW list each time
```

### Quick Revision
- Definition: List = ordered, mutable, allows duplicates.
- Trap: `sort()` returns `None`; `[[x]*n]*n` shares references.
- Interview answer: "Ordered, mutable, allows duplicates and mixed types."
- Remember: **List = ordered + mutable + duplicates allowed.**

## 9.2 Tuples

### Definition
> A tuple is a built-in, ordered, immutable collection that can hold values of different types and allows duplicates.

### Easy Meaning
A tuple looks like a list, but once you create it, you can't add, remove, or change its elements.

### Remember It
**Tuple = ordered + immutable + duplicates allowed.**

### Why is it used?
Tuples are used for fixed collections of related values (like coordinates `(x, y)`), for returning multiple values from a function, and as dictionary keys (since they're hashable, if their contents are hashable too).

### Simple Example
```python
point = (3, 4)
single = (5,)      # comma required! (5) is just an int
```

### Important Differences: List vs Tuple

| Aspect | List | Tuple |
|---|---|---|
| Mutable | Yes | No |
| Syntax | `[]` | `()` |
| Hashable | No | Yes (if elements are hashable) |
| Performance | Slightly slower | Slightly faster, more compact |
| Typical use | Data that changes | Fixed records, dict keys |

### Common Mistakes
- Writing `(5)` expecting a tuple — it's just the integer `5` in parentheses. You need `(5,)`.
- Assuming nothing inside a tuple can ever change — a tuple holding a list still allows that inner list to be mutated.

### Interview Question
**Q: What is the difference between a list and a tuple?**

### Short Interview Answer
"Both store ordered collections of items and allow duplicates, but a list is mutable — we can change it after creating it — while a tuple is immutable, so once created, it can't be changed. Because tuples are immutable, they can be used as dictionary keys, unlike lists."

### Interview Depth Levels
**Basic:** Give one example each of a list and a tuple.
**Intermediate:** Why can tuples be used as dictionary keys but lists can't?
**Tricky:** If a tuple contains a list, can that list still be modified? Does this contradict tuple immutability?
*(Tricky answer: Yes it can still be modified, and no it doesn't contradict immutability — the tuple guarantees its own references don't change, not that everything reachable through those references is frozen.)*

## 9.3 Sets and Frozensets

### Definition
> A set is a built-in, unordered collection of unique, hashable elements. A frozenset is the immutable version of a set.

### Easy Meaning
A set is like a list, but it automatically removes duplicates and doesn't keep any particular order. A frozenset is a set you're no longer allowed to change.

### Remember It
**Set = unique + unordered + mutable. Frozenset = unique + unordered + immutable.**

### Why is it used?
Sets are used for fast membership testing (checking if something exists) and for mathematical operations like union, intersection, and difference — much faster than doing the same with lists.

### Simple Example
```python
s = {1, 2, 3}
s.add(4)
print(3 in s)   # True -- O(1) average, much faster than list's O(n)
```

### Common Mistakes
- Writing `{}` expecting an empty set — it actually creates an empty **dictionary**. Use `set()` instead.
- Trying to put an unhashable object, like a list, inside a set.

### Interview Question
**Q: Why is checking membership in a set faster than in a list?**

### Short Interview Answer
"Sets are backed by a hash table internally, so checking whether an item exists is roughly O(1) on average — Python can jump almost directly to where the item would be. Lists have to check elements one at a time, which is O(n), so sets are much faster for membership testing on large collections."

### Important Differences: Set vs Frozenset

| Aspect | Set | Frozenset |
|---|---|---|
| Mutable | Yes | No |
| Hashable | No | Yes |
| Can be a dict key or set element | No | Yes |

## 9.4 Dictionaries

### Definition
> A dictionary is a built-in, mutable mapping that stores data as key-value pairs, where each key must be unique and hashable.

### Easy Meaning
A dictionary lets you look something up by a name (key) instead of by its position — like a real dictionary where you look up a word to find its meaning.

### Remember It
**Dict = key → value, keys must be unique and hashable.**

### Why is it used?
Dictionaries are used whenever you need fast lookups by a meaningful label instead of a numeric position — like looking up a user's data by their username, or counting how many times each word appears in a document.

### Simple Example
```python
person = {"name": "Ana", "age": 30}
print(person["name"])          # "Ana"
person["age"] = 31               # update
person["city"] = "Delhi"          # add new key
```

### Realistic Example
```python
word_counts = {}
for word in "the cat sat on the mat".split():
    word_counts[word] = word_counts.get(word, 0) + 1
print(word_counts)   # {'the': 2, 'cat': 1, 'sat': 1, 'on': 1, 'mat': 1}
```

### Common Mistakes
- Using a list as a dictionary key — raises `TypeError: unhashable type: 'list'`.
- Using `d[key]` instead of `d.get(key)` when the key might not exist — causes a `KeyError` instead of returning a safe default.

### Interview Question
**Q: What is a dictionary in Python?**

### Short Interview Answer
"A dictionary is a built-in Python data structure that stores data as key-value pairs. It's mutable, and each key must be unique and hashable. Dictionaries are commonly used when we need fast lookup of a value using a key."

### Detailed Explanation
Internally, a dictionary is implemented using a hash table. When you insert a key-value pair, Python computes a hash of the key to decide where to store it, which is what makes lookups fast — close to O(1) on average. Because the hash of an object should never change during its lifetime for hashing to work correctly, dictionary keys must be immutable (or at least consistently hashable) — this is exactly why lists can't be used as keys, but tuples can, as long as everything inside the tuple is also hashable.

### How I Would Answer in an Interview
"A dictionary stores data as key-value pairs, kind of like a real-world dictionary where you look up a word to get its meaning. In Python, keys have to be unique and hashable — so strings, numbers, and tuples work as keys, but lists don't, since lists are mutable and can't be hashed reliably."

### Follow-up Questions
1. Why does a dictionary key need to be hashable? — **Because dictionaries use a hash table internally; the key's hash determines where it's stored, and that hash must stay consistent for lookups to work correctly, which requires the key to be effectively immutable.**
2. What happens if you access a missing key with `d[key]`? — **Raises `KeyError`. Use `.get(key, default)` to avoid this.**
3. What's the difference between `dict.update()` and the `|` merge operator? — **`update()` mutates the dict in place; `|` (Python 3.9+) creates a brand-new merged dict, leaving both originals untouched.**

### Predict the Output
```python
d1 = {"a": 1}
d2 = {"a": 2, "b": 3}
merged = d1 | d2
print(merged, d1)
```
**Answer:** `{'a': 2, 'b': 3} {'a': 1}`
**Explanation:** The `|` operator (Python 3.9+) creates a new dictionary; when keys overlap, the right-hand dict's value wins. The original `d1` is untouched.
**Interview Concept Tested:** Whether the candidate knows the modern dict merge operator and that it doesn't mutate.

### Important Differences: Dict vs Set

| Aspect | Dict | Set |
|---|---|---|
| Stores | Key → value pairs | Unique elements only |
| Syntax | `{k: v}` | `{v1, v2}` |
| Empty literal | `{}` | `set()` — NOT `{}`! |

### Common Interview Trap
**Wrong thinking:** "`{}` creates an empty set."
**Correct thinking:** `{}` always creates an empty dictionary. An empty set must be created with `set()`.
**What to say in the interview:** "I'd double check — `{}` is actually an empty dict by default in Python; for an empty set, you have to explicitly write `set()`."

### Coding Practice
**Beginner:** Count how many times each character appears in a string using a dictionary.
**Intermediate:** Given a list of dictionaries representing students, build a new dictionary mapping student name to grade using a dict comprehension.

### Quick Revision
- Definition: Dict = key-value pairs, keys unique and hashable.
- Trap: `{}` is an empty dict, not an empty set.
- Interview answer: "Stores key-value pairs; keys must be unique and hashable; used for fast lookup."
- Remember: **Dict = key → value, keys must be unique and hashable.**

## 9.5 Slicing

### Definition
> Slicing extracts a portion of a sequence (like a list, tuple, or string) using the syntax `sequence[start:stop:step]`, and it never raises an error even if the requested range goes out of bounds.

### Easy Meaning
Slicing lets you grab a "chunk" of a sequence by saying where to start and stop, and it's forgiving if you ask for more than exists.

### Remember It
**Slicing clamps out-of-range bounds silently. Direct indexing raises `IndexError`.**

### Simple Example
```python
lst = [0, 1, 2, 3, 4, 5]
print(lst[1:4])      # [1, 2, 3]
print(lst[::-1])       # reversed
print(lst[2:100])       # [2, 3, 4, 5] -- no error, even though 100 is out of range
print(lst[100])           # IndexError! Direct indexing is strict
```

### Interview Question
**Q: Why doesn't slicing raise an `IndexError` for out-of-range indices, while direct indexing does?**

### Short Interview Answer
"Slicing is designed to be forgiving — it automatically clamps the requested range to the sequence's actual bounds, so asking for more than exists just gives you what's available. Direct indexing, on the other hand, is asking for one specific position, so if that position doesn't exist, it correctly raises an `IndexError`."

## 9.6 Comprehensions and Their Scope

### Definition
> A comprehension is a compact way to build a list, set, or dictionary in a single line, using a `for` clause inside brackets. In Python 3, comprehensions have their own local scope, so their loop variable does not leak into the surrounding code.

### Easy Meaning
Comprehensions are a shortcut for writing a `for` loop that builds a collection, and the variable used inside doesn't "escape" outside of it.

### Remember It
**Comprehension loop variables stay inside the comprehension — no leaking in Python 3.**

### Simple Example
```python
squares = [x**2 for x in range(5)]
print(squares)   # [0, 1, 4, 9, 16]
```

### Predict the Output
```python
x = "outer"
squares = [x for x in range(5)]
print(x)
```
**Answer:** `"outer"`
**Explanation:** In Python 3, the comprehension's `x` exists only inside the comprehension's own scope — it does not overwrite the outer `x`. (This differs from Python 2, where list comprehensions did leak their loop variable.)
**Interview Concept Tested:** Knowledge of the Python 2 vs Python 3 scoping change for comprehensions.

### Interview Question
**Q: Does a variable used inside a list comprehension leak into the surrounding scope?**

### Short Interview Answer
"No, not in Python 3. List comprehensions have their own local scope, so the loop variable used inside doesn't affect or overwrite a variable with the same name outside the comprehension. This was actually different in Python 2, where it did leak."

## 9.7 Unpacking

### Definition
> Unpacking lets you assign multiple values from a sequence to multiple variables in one line, including using `*` to collect "the rest" of the values into a list.

### Easy Meaning
Unpacking splits a sequence into separate named pieces in one line, instead of accessing each item by index manually.

### Remember It
**`*rest` grabs "everything else" as a list.**

### Simple Example
```python
a, b, c = [1, 2, 3]
first, *middle, last = [1, 2, 3, 4, 5]
print(first, middle, last)   # 1 [2, 3, 4] 5
```

### Interview Question
**Q: What does the `*` symbol do during unpacking, like in `a, *rest = [1, 2, 3, 4]`?**

### Short Interview Answer
"It collects all the remaining values into a list. So in `a, *rest = [1, 2, 3, 4]`, `a` becomes `1` and `rest` becomes `[2, 3, 4]`. It's a convenient way to grab the first (or last) item and keep the rest as a group, without manually slicing."
