# Chapter 10 — Functions In-Depth

## 10.1 What is a Function? (Refresher + Deepened)

### Definition
> A function is a named, reusable block of code that performs a specific task, optionally takes inputs (parameters), and optionally returns an output.

### Easy Meaning
A function is a mini-program you can call by name whenever you need to repeat a task, instead of writing the same code again and again.

### Remember It
**Function = reusable block of logic you can call by name.**

### Why is it used?
Functions avoid code duplication, make programs easier to test and debug, and let you break a big problem into small, manageable pieces.

### Simple Example
```python
def greet(name):
    return f"Hello, {name}!"

print(greet("Ana"))
```

### Interview Question
**Q: What is a function, and why do we use them?**

### Short Interview Answer
"A function is a reusable block of code that performs a specific task. We use functions to avoid repeating code, make programs easier to read and maintain, and to break complex problems into smaller, testable pieces."

## 10.2 Positional, Keyword, and Default Arguments

### Definition
> Positional arguments are matched to parameters by their order. Keyword arguments are matched by explicitly naming the parameter. Default arguments provide a fallback value used when the caller doesn't supply that argument.

### Easy Meaning
Positional = order matters. Keyword = you say which parameter you mean by name. Default = "use this value if nothing is given."

### Remember It
**Positional = order. Keyword = name. Default = fallback value.**

### Simple Example
```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Ana"))                  # positional + default
print(greet("Ana", "Hi"))              # positional
print(greet(name="Ana", greeting="Hi")) # keyword
print(greet(greeting="Hi", name="Ana")) # keyword -- order doesn't matter here
```

### Common Mistakes
- Putting a positional argument after a keyword argument in a call — causes `SyntaxError`.
- Assuming default argument values are recalculated every call (they are not — see the mutable default trap below).

## 10.3 The Mutable Default Argument Trap (High-Value Interview Topic)

### Definition
> A mutable default argument (like a list or dict) is created only once, when the function is defined — not each time the function is called. This means every call that relies on the default shares and mutates the *same* object.

### Easy Meaning
If you use `def f(x=[])`, that empty list is made just one time, ever — not fresh for every call. So every call without an argument reuses and can permanently change that same list.

### Remember It
**Default values are evaluated ONCE, at function definition time — not on every call.**

### Simple Example (The Bug)
```python
def add_item(item, cart=[]):
    cart.append(item)
    return cart

print(add_item("apple"))    # ['apple']
print(add_item("banana"))    # ['apple', 'banana']  -- unexpected! Same list reused.
```

### The Fix
```python
def add_item(item, cart=None):
    if cart is None:
        cart = []
    cart.append(item)
    return cart
```

### Interview Question
**Q: Why is using a mutable default argument, like `def f(x=[])`, considered dangerous in Python?**

### Short Interview Answer
"Default argument values are evaluated only once, when the function is defined, not each time it's called. So if the default is a mutable object like a list, every call that doesn't provide that argument ends up sharing and mutating the same object, which usually isn't what the developer intended. The standard fix is to use `None` as the default and create the mutable object inside the function body."

### Detailed Explanation
When Python defines a function, it evaluates the default argument expressions exactly once and stores the resulting objects with the function object itself. Every subsequent call that omits that argument reuses the same stored object. If that object is mutable and gets mutated inside the function (like appending to a list), those changes persist across calls, since it's literally the same object each time — this connects directly back to Chapter 3's identity/mutability concepts.

### How I Would Answer in an Interview
"This is actually a classic Python gotcha. If you write `def f(x=[])`, that empty list gets created just once, when the function is defined — not fresh every time you call it. So if you mutate it inside the function, that change sticks around for the next call too. The safe pattern is to default to `None` and create the actual list inside the function body."

### Common Interview Trap
**Wrong thinking:** "Default arguments are recreated fresh every time the function runs, like local variables."
**Correct thinking:** Defaults are evaluated once at function *definition* time and reused across all calls that rely on them.
**What to say in the interview:** "I always avoid mutable defaults directly — I use `None` as a sentinel and build the actual object inside the function, to sidestep this shared-state bug entirely."

### Predict the Output
```python
def append_to(item, target=[]):
    target.append(item)
    return target

print(append_to(1))
print(append_to(2))
print(append_to(3, []))
print(append_to(4))
```
**Answer:** `[1]`, `[1, 2]`, `[3]`, `[1, 2, 4]`
**Explanation:** Calls without an explicit `target` share the same default list, which keeps growing. The call with an explicit `[]` uses a fresh list instead, unaffected by the shared default.
**Interview Concept Tested:** Deep understanding of when defaults are created and shared.

### Quick Revision
- Definition: Defaults are created once, at def time.
- Fix: use `None` as sentinel default.
- Remember: **Default values are evaluated ONCE, at function definition time.**

## 10.4 `*args` and `**kwargs`

### Definition
> `*args` collects any extra positional arguments into a tuple. `**kwargs` collects any extra keyword arguments into a dictionary.

### Easy Meaning
`*args` = "give me however many extra plain values you want, I'll bundle them into a tuple." `**kwargs` = "give me however many extra named values you want, I'll bundle them into a dict."

### Remember It
**`*args` → tuple of extra positional args. `**kwargs` → dict of extra keyword args.**

### Simple Example
```python
def demo(*args, **kwargs):
    print(args)
    print(kwargs)

demo(1, 2, 3, name="Ana", age=30)
# (1, 2, 3)
# {'name': 'Ana', 'age': 30}
```

### Realistic Example
```python
def make_request(url, **params):
    query = "&".join(f"{k}={v}" for k, v in params.items())
    return f"{url}?{query}"

print(make_request("/search", q="python", page=2))
# /search?q=python&page=2
```

### Interview Question
**Q: What are `*args` and `**kwargs` used for?**

### Short Interview Answer
"`*args` lets a function accept any number of extra positional arguments, collected as a tuple. `**kwargs` lets it accept any number of extra keyword arguments, collected as a dictionary. They're useful when you don't know in advance how many arguments the caller will pass, or when writing wrapper/decorator functions that need to forward arguments."

## 10.5 Positional-Only and Keyword-Only Parameters

### Definition
> Positional-only parameters (marked with `/`) must be passed by position, not by name. Keyword-only parameters (marked with `*`) must be passed by name, not by position.

### Easy Meaning
`/` locks certain parameters to "position only, no naming allowed." `*` locks certain parameters to "must be named, no position allowed."

### Remember It
**Everything before `/` = positional-only. Everything after `*` = keyword-only.**

### Simple Example
```python
def f(a, b, /, c, d, *, e, f):
    pass
# a, b -- positional-only
# c, d -- positional or keyword
# e, f -- keyword-only
```

### Interview Question
**Q: What's the purpose of positional-only and keyword-only parameters?**

### Short Interview Answer
"They give the function author more control over the calling convention. Positional-only parameters prevent callers from relying on internal parameter names, which is useful for API stability. Keyword-only parameters force callers to be explicit about what they're passing, which improves readability for functions with several similar-looking arguments."

## 10.6 Scope: LEGB Rule, `global`, and `nonlocal`

### Definition
> LEGB describes the order Python searches for a variable name: Local, Enclosing, Global, Built-in. `global` lets a function modify a variable in the module's global scope. `nonlocal` lets a nested function modify a variable in its enclosing (but not global) scope.

### Easy Meaning
When Python looks for a variable, it checks your current function first, then any function wrapping it, then the whole file, then Python's built-in names — in that order. `global` and `nonlocal` are special permission slips to modify a variable that lives outside your current function.

### Remember It
**LEGB = Local → Enclosing → Global → Built-in.**

### Simple Example
```python
x = "global"

def outer():
    x = "enclosing"
    def inner():
        nonlocal x
        x = "changed by inner"
    inner()
    print(x)   # "changed by inner"

outer()
print(x)   # "global" -- untouched
```

### Common Mistakes
- Trying to modify a global variable inside a function without declaring `global` — this creates a *new local* variable instead, and raises `UnboundLocalError` if you try to read it before "assigning" it.
- Confusing `global` (for module-level scope) with `nonlocal` (for enclosing function scope) — they are not interchangeable.

### Interview Question
**Q: What is the LEGB rule?**

### Short Interview Answer
"LEGB describes the order in which Python looks up a variable name — first in the Local scope, then any Enclosing function's scope, then the module's Global scope, and finally Python's Built-in names. It explains how Python resolves which variable you're referring to when there are multiple variables with the same name at different scopes."

### Predict the Output
```python
def outer():
    x = 10
    def inner():
        print(x)
        x = 20
    inner()

outer()
```
**Answer:** `UnboundLocalError: local variable 'x' referenced before assignment`
**Explanation:** Because `inner()` assigns to `x` anywhere in its body, Python treats `x` as local to `inner()` for the *entire* function — including the `print(x)` line before the assignment. It does not fall back to the enclosing scope's `x`, because the presence of the assignment makes Python decide, at compile time, that `x` is local.
**Interview Concept Tested:** Deep understanding that scope is determined statically per-function, not line-by-line.

### Common Interview Trap
**Wrong thinking:** "Python will just read the outer `x` until the line where I reassign it."
**Correct thinking:** If a name is assigned anywhere inside a function, Python treats it as local for the whole function body — this is decided at compile time, not at runtime, so it applies even to the lines before the assignment.
**What to say in the interview:** "This is why we need `nonlocal` — without it, an assignment anywhere in the function makes Python treat that name as local everywhere in that function, causing an `UnboundLocalError` if you tried to read it first."

### Quick Revision
- Definition: LEGB = variable lookup order.
- Trap: assignment anywhere in a function makes that name local for the whole function.
- Remember: **LEGB = Local → Enclosing → Global → Built-in.**
