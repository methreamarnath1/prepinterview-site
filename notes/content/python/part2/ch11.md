# Chapter 11 — Closures & Recursion

## 11.1 Closures

### Definition
> A closure is a function that "remembers" variables from its enclosing scope, even after that enclosing function has finished running.

### Easy Meaning
A closure is like a function with a backpack — it carries around some variables from where it was created, even after it leaves that place.

### Remember It
**Closure = function + remembered variables from where it was defined.**

### Why is it used?
Closures let you create functions with pre-configured behavior (like a counter that remembers its own count) without using a full class.

### Simple Example
```python
def make_multiplier(n):
    def multiplier(x):
        return x * n
    return multiplier

times3 = make_multiplier(3)
print(times3(10))   # 30 -- multiplier still remembers n=3
```

### The Late-Binding Closure Trap (Very Common Interview Trap)

### Definition
> Late binding means a closure looks up the value of a variable at the time it's *called*, not at the time it was *created* — this causes surprising results when closures are created inside a loop.

### Simple Example (The Bug)
```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)

print([f() for f in funcs])   # [2, 2, 2] -- NOT [0, 1, 2]!
```

### Why does this happen?
All three lambdas share the *same* variable `i` from the enclosing scope. By the time they're called, the loop has finished and `i` is `2` for all of them.

### The Fix
```python
funcs = []
for i in range(3):
    funcs.append(lambda i=i: i)   # default argument captures the CURRENT value immediately

print([f() for f in funcs])   # [0, 1, 2]
```

### Interview Question
**Q: What is the closure late-binding trap, and how do you fix it?**

### Short Interview Answer
"When you create closures inside a loop, they don't capture the loop variable's value at creation time — they capture the variable itself, and look it up when actually called. So if all the closures are called after the loop finishes, they all see the final value of the loop variable. The common fix is to capture the current value using a default argument, like `lambda i=i: i`."

### Detailed Explanation
This happens because closures in Python capture variables by reference to the enclosing scope, not by value at the time the closure is created. The loop variable `i` is a single variable that gets reassigned on each iteration; all the lambdas defined inside the loop refer to that same variable, not separate snapshots of it. Using a default argument works because default argument values *are* evaluated at function-definition time (see Chapter 10.3), so `i=i` freezes the current value into the function's own default at the moment each lambda is created.

### Common Interview Trap
**Wrong thinking:** "Each lambda created in the loop captures the value of `i` at that point in the loop."
**Correct thinking:** All the lambdas share a single reference to the same variable `i`, and they only look up its value when called — by then, the loop has already finished.
**What to say in the interview:** "I'd explain this is a late-binding issue, and the fix is to force early binding using a default argument, like `lambda i=i: i`, which captures the value immediately rather than the variable itself."

### Predict the Output
```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)
print([f() for f in funcs])
```
**Answer:** `[2, 2, 2]`
**Explanation:** As above — all closures share the same `i`, which is `2` after the loop ends.
**Interview Concept Tested:** Late binding in closures — one of the most common Python "gotcha" interview questions.

### Quick Revision
- Definition: Closure = function + remembered enclosing variables.
- Trap: closures in a loop share the loop variable by reference (late binding).
- Fix: default argument `lambda i=i: i`.
- Remember: **Closures capture variables, not values — unless you force it with a default argument.**

## 11.2 Recursion

### Definition
> Recursion is when a function calls itself, usually to break a problem down into smaller sub-problems, with a base case that stops the recursion.

### Easy Meaning
A recursive function solves a big problem by solving a smaller version of the same problem, again and again, until it reaches a simple case it can answer directly.

### Remember It
**Recursion = base case (stops it) + recursive case (calls itself with a smaller problem).**

### Simple Example
```python
def factorial(n):
    if n <= 1:          # base case
        return 1
    return n * factorial(n - 1)   # recursive case

print(factorial(5))   # 120
```

### Common Mistakes
- Forgetting the base case, causing infinite recursion until `RecursionError: maximum recursion depth exceeded`.
- Using recursion for problems that would be simpler and more efficient as a loop, without considering Python's lack of proper tail-call optimization.

### Interview Question
**Q: What is recursion, and what's a risk of using it in Python?**

### Short Interview Answer
"Recursion is when a function calls itself to solve smaller versions of the same problem, until it reaches a base case that stops it. A risk in Python specifically is that it doesn't optimize tail calls the way some other languages do, so deep recursion can hit Python's recursion limit and raise a `RecursionError` — for very deep problems, an iterative solution is often safer."
