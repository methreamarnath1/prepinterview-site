# Chapter 13 — Iterables & Iterators

## 13.1 Iterable vs Iterator

### Definition
> An iterable is any object you can loop over — it implements `__iter__()`, which returns an iterator. An iterator is an object that produces one item at a time and keeps track of its own position, implementing both `__iter__()` and `__next__()`.

### Easy Meaning
An iterable is something you *can* go through, like a book. An iterator is the actual bookmark that remembers where you currently are and gives you the next page when asked.

### Remember It
**Iterable = can be looped over. Iterator = actively remembers position, gives next item.**

### Why is this important?
Understanding this distinction explains how `for` loops actually work internally, and is the foundation for understanding generators (Chapter 14).

### How it works
1. A `for` loop calls `iter(iterable)` to get an iterator.
2. It repeatedly calls `next(iterator)` to get each item.
3. When there are no more items, `next()` raises `StopIteration`, and the loop stops automatically (you never see this exception in normal `for` loop usage).

### Simple Example
```python
lst = [1, 2, 3]
it = iter(lst)
print(next(it))   # 1
print(next(it))    # 2
print(next(it))     # 3
print(next(it))      # StopIteration!
```

### Important Differences: Iterable vs Iterator

| Aspect | Iterable | Iterator |
|---|---|---|
| Has `__iter__` | Yes | Yes (returns itself) |
| Has `__next__` | No | Yes |
| Can restart from beginning | Yes (get a new iterator) | No — it's stateful, exhausted once done |
| Example | `list`, `str`, `dict` | The object `iter(some_list)` returns |

### Interview Question
**Q: What's the difference between an iterable and an iterator?**

### Short Interview Answer
"An iterable is anything you can loop over, like a list — it has an `__iter__` method that returns an iterator. An iterator is the object that actually produces items one at a time and remembers its current position — it has both `__iter__` and `__next__`. All iterators are iterables, but not all iterables are iterators — a list is iterable, but it's not itself an iterator, since it doesn't track its own position."

### Detailed Explanation
This is exactly how a `for` loop works behind the scenes: `for x in some_list:` internally calls `iter(some_list)` to get an iterator, then repeatedly calls `next()` on it until `StopIteration` is raised, at which point the loop ends automatically. This is called the iterator protocol. Once an iterator is exhausted, it stays exhausted — calling `iter()` on it again just returns itself, still empty, which is different from an iterable like a list, which can produce a brand-new, fresh iterator every time.

### How I Would Answer in an Interview
"An iterable is something you can iterate over — like a list. An iterator is the object that does the actual work of walking through it one item at a time and remembering where it is. Every iterator is also an iterable, technically, but a plain list isn't an iterator itself — it has to give you an iterator first, using `iter()`, before you can call `next()` on it."

### Follow-up Questions
1. What exception signals the end of iteration? — **`StopIteration`.**
2. Can you reuse an exhausted iterator? — **No — once exhausted, it stays exhausted; you need a new iterator.**
3. How would you build your own custom iterator class? — *(Answered fully in section 13.2.)*

### Common Interview Trap
**Wrong thinking:** "A list is an iterator because I can use it in a `for` loop."
**Correct thinking:** A list is an iterable — it can *produce* an iterator via `iter()`, but the list object itself doesn't track iteration state or implement `__next__`.
**What to say in the interview:** "I'd clarify that a list is iterable, not itself an iterator — calling `iter()` on it is what actually gives you an iterator object."

## 13.2 Building a Custom Iterator

### Simple Example
```python
class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1

for num in Countdown(3):
    print(num)   # 3, 2, 1
```

### Interview Question
**Q: What two methods must a class implement to be a proper iterator?**

### Short Interview Answer
"It needs `__iter__`, which usually just returns `self`, and `__next__`, which returns the next value each time it's called and raises `StopIteration` when there are no more values left. Together, these two methods make up what's called the iterator protocol."
