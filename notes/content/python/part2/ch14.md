# Chapter 14 — Generators

## 14.1 What is a Generator?

### Definition
> A generator is a special kind of function that produces a sequence of values lazily, one at a time, using the `yield` keyword instead of `return`, without storing the entire sequence in memory at once.

### Easy Meaning
A generator is like a function that pauses itself every time it hands you a value, and picks up right where it left off the next time you ask for another one.

### Remember It
**Generator = function with `yield` = produces values one at a time, lazily.**

### Why is it used?
Generators save memory — instead of building a huge list all at once, they produce values on demand. This is essential for working with very large or even infinite sequences.

### How it works
1. Calling a generator function does NOT run its code immediately — it returns a generator object.
2. Each call to `next()` on that generator runs the function until it hits a `yield`, then pauses there.
3. The next `next()` call resumes exactly where it left off, continuing until the next `yield` or the function ends.
4. When the function ends, `StopIteration` is raised automatically.

### Simple Example
```python
def count_up_to(n):
    i = 1
    while i <= n:
        yield i
        i += 1

for num in count_up_to(3):
    print(num)   # 1, 2, 3
```

### Realistic Example
```python
def read_large_file(path):
    with open(path) as f:
        for line in f:
            yield line.strip()

# Processes one line at a time -- never loads the whole file into memory
for line in read_large_file("huge_log.txt"):
    if "ERROR" in line:
        print(line)
```

### Important Differences: Generator vs List

| Aspect | List | Generator |
|---|---|---|
| Memory | Stores all items at once | Produces items one at a time |
| Speed to create | Slower for large data | Instant — nothing computed yet |
| Can be re-iterated | Yes | No — exhausted after one pass |
| Access by index | Yes (`lst[5]`) | No |

### Interview Question
**Q: What is a generator, and why would you use one instead of a list?**

### Short Interview Answer
"A generator is a function that uses `yield` to produce values one at a time, instead of building and returning a whole collection at once. It's useful when working with large datasets, because it doesn't hold everything in memory — it computes each value only when it's actually needed. The trade-off is that a generator can only be iterated once, and you can't randomly access items by index like you can with a list."

### Detailed Explanation
When Python encounters `yield` inside a function, that function becomes a generator function. Calling it doesn't execute any code right away — it returns a generator object. Each time `next()` is called on that generator (which happens automatically inside a `for` loop), the function's code runs until it hits a `yield` statement, at which point it pauses, remembering all of its local state — variables, the exact line it stopped at, everything — and returns the yielded value. The next `next()` call resumes execution from exactly that point. This "pause and resume" behavior is what makes generators memory-efficient, since only one value needs to exist in memory at a time, unlike a list comprehension which builds the entire result upfront.

### How I Would Answer in an Interview
"A generator is a way to produce a sequence of values without building the whole thing in memory at once. Instead of `return`, you use `yield`, and every time you call `next()` on it, it runs until the next `yield` and pauses there. I'd use it for something like processing a huge file line by line, where loading everything into a list at once would use too much memory."

### Follow-up Questions
1. What's the difference between a generator function and a generator expression? — **A generator function uses `def` and `yield`; a generator expression is a compact, one-line version using parentheses, like `(x**2 for x in range(10))`.**
2. Can you iterate over a generator twice? — **No — once exhausted, it's done; you'd need to call the generator function again to get a fresh one.**
3. What does `yield from` do? — *(Answered next.)*

## 14.2 `yield from`

### Definition
> `yield from` delegates part of a generator's work to another iterable or generator, yielding all of its values as if they came from the outer generator directly.

### Simple Example
```python
def inner():
    yield 1
    yield 2

def outer():
    yield "start"
    yield from inner()
    yield "end"

print(list(outer()))   # ['start', 1, 2, 'end']
```

### Interview Question
**Q: What does `yield from` do, and why is it useful?**

### Short Interview Answer
"`yield from` lets a generator delegate to another iterable or generator, yielding each of its values in turn, without writing a manual loop. It's especially useful for composing generators — for example, flattening nested generators — and it also properly forwards values sent into the generator, which a manual loop wouldn't do automatically."

## 14.3 Generator Expressions

### Definition
> A generator expression is a compact, lazy version of a list comprehension, written with parentheses instead of square brackets.

### Simple Example
```python
squares = (x**2 for x in range(1000000))   # instant -- nothing computed yet
print(next(squares))   # 0
```

### Interview Question
**Q: What's the difference between `[x for x in range(10)]` and `(x for x in range(10))`?**

### Short Interview Answer
"The first is a list comprehension — it builds and stores the full list immediately in memory. The second is a generator expression — it creates a generator object that produces values lazily, one at a time, only computing each value when it's actually requested."

## 14.4 Generator Methods: `send()`, `throw()`, `close()`

### Definition
> `send(value)` resumes a paused generator and sends a value into it, which becomes the result of the `yield` expression that was paused. `throw(exception)` raises an exception inside the generator at the point it's paused. `close()` stops the generator early by raising `GeneratorExit` inside it.

### Simple Example
```python
def echo():
    while True:
        received = yield
        print(f"Received: {received}")

gen = echo()
next(gen)          # "prime" the generator -- runs until the first yield
gen.send("hello")   # Received: hello
gen.close()           # stops the generator
```

### Interview Question
**Q: What does `generator.send()` do?**

### Short Interview Answer
"`send()` resumes a paused generator and passes a value into it, which becomes the value of the `yield` expression at that pause point. It's how you can have two-way communication with a generator, not just pulling values out of it, but also pushing values in — this is the foundation of how coroutine-style generators work."

### Common Interview Trap
**Wrong thinking:** "You can call `send()` on a generator immediately after creating it."
**Correct thinking:** You must first advance the generator to its first `yield` (usually with a `next()` call) before you can `send()` a meaningful value into it — sending to a brand-new, unstarted generator raises a `TypeError`.
**What to say in the interview:** "I'd remember to 'prime' the generator with a `next()` call first, since `send()` needs the generator to already be paused at a `yield`."

### Coding Practice
**Beginner:** Write a generator function that yields the squares of numbers from 1 to n.
**Intermediate:** Write a generator that reads a large list in chunks of a given size, yielding one chunk at a time.
**Advanced:** Write a generator pipeline — one generator that filters even numbers, feeding into another that squares them — using `yield from` to compose them.

### Quick Revision
- Definition: Generator = function using `yield`, produces values lazily.
- Trap: must "prime" with `next()` before `send()`.
- Interview answer: "Produces one value at a time using `yield`; memory-efficient; single-pass only."
- Remember: **Generator = function with `yield` = produces values one at a time, lazily.**
