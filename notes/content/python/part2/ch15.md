# Chapter 15 — Modules & Packages

## 15.1 Modules, Packages, and the Import System

### Definition
> A module is a single `.py` file containing Python code that can be imported and reused. A package is a folder containing multiple modules, usually with an `__init__.py` file, organized as a namespace.

### Easy Meaning
A module is one file of reusable code. A package is a folder full of related modules, bundled together under one name.

### Remember It
**Module = one file. Package = folder of modules.**

### Simple Example
```python
# mymath.py
def add(a, b):
    return a + b

# main.py
import mymath
print(mymath.add(2, 3))   # 5

from mymath import add
print(add(2, 3))            # 5
```

### Interview Question
**Q: What's the difference between a module and a package?**

### Short Interview Answer
"A module is a single Python file containing code you can import and reuse. A package is a directory containing multiple related modules, typically identified by an `__init__.py` file, which groups them together under one importable namespace."

## 15.2 `__name__ == "__main__"`

### Definition
> `__name__` is a special built-in variable that Python sets automatically. If a file is run directly, `__name__` is set to `"__main__"`. If the same file is imported into another file, `__name__` is set to the module's actual name instead.

### Easy Meaning
This lets a file know whether it's being run directly by you, or being borrowed by another file through an import — and behave differently depending on which one it is.

### Remember It
**`__name__ == "__main__"` → "this file was run directly, not imported."**

### Simple Example
```python
# script.py
def main():
    print("Running directly")

if __name__ == "__main__":
    main()
```
If you run `python script.py`, `main()` runs. If you `import script` from another file, `main()` does NOT run automatically.

### Interview Question
**Q: Why do we use `if __name__ == "__main__":` in Python scripts?**

### Short Interview Answer
"It lets a file distinguish between being run directly versus being imported as a module elsewhere. Code inside that block only runs when the file is executed directly — if someone imports the file to reuse its functions, that block is skipped, which avoids accidentally running test code or a main routine just from importing it."

### Common Interview Trap
**Wrong thinking:** "`__name__` is always equal to the filename."
**Correct thinking:** `__name__` equals `"__main__"` only when the file is run directly. When imported, `__name__` equals the module's actual name (like `"mymath"`), not `"__main__"`.

## 15.3 Module Caching & Circular Imports

### Definition
> Python caches every module it imports in `sys.modules`, so importing the same module multiple times only actually runs its code once. A circular import happens when two modules import each other, directly or indirectly, which can cause one of them to receive a partially initialized module.

### Easy Meaning
Once Python loads a module, it remembers it and won't reload it again — it just hands you the already-loaded version. Circular imports happen when Module A needs Module B, and Module B needs Module A back, which can confuse Python about what's actually ready yet.

### Remember It
**Modules are only executed once — cached in `sys.modules` after the first import.**

### Simple Example (Circular Import Problem)
```python
# a.py
import b
def func_a():
    return b.func_b()

# b.py
import a
def func_b():
    return a.func_a()   # ImportError or AttributeError depending on import order
```

### Common Mistakes
- Structuring code so two modules depend on each other at import time, causing `ImportError`/`AttributeError`.
- Assuming re-importing a module re-runs its top-level code — it doesn't, due to caching.

### Interview Question
**Q: What is a circular import, and how would you fix one?**

### Short Interview Answer
"A circular import happens when two modules import each other, so Python ends up trying to load one before the other has finished initializing. Common fixes include moving the import inside a function instead of the top of the file, so it's only resolved when actually needed, restructuring code to remove the mutual dependency, or combining the two modules if they're too tightly coupled."

### Quick Revision
- Definition: Module = one file, Package = folder of modules.
- `__name__ == "__main__"` distinguishes direct run vs import.
- Modules are cached — only run once, no matter how many times imported.
- Remember: **Module = one file. Package = folder of modules. Cached after first import.**
