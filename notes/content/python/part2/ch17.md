# Chapter 17 — File Handling & Data Formats

## 17.1 File Handling with `open()` and Context Managers

### Definition
> `open()` opens a file and returns a file object you can read from or write to. Using it inside a `with` statement (a context manager) guarantees the file is automatically closed, even if an error occurs.

### Easy Meaning
`open()` gives you access to a file. `with` makes sure you don't forget to close it — Python closes it for you automatically once you're done.

### Remember It
**Always use `with open(...) as f:` — it auto-closes the file, even on error.**

### Simple Example
```python
with open("data.txt", "r") as f:
    content = f.read()

with open("data.txt", "w") as f:
    f.write("Hello, file!")
```

### Common Mistakes
- Opening a file without `with`, then forgetting to call `.close()` — can leak file handles or leave data unwritten (unflushed buffers).
- Confusing text mode (`"r"`) with binary mode (`"rb"`) when working with non-text files like images.

### Interview Question
**Q: Why is it recommended to use `with open(...)` instead of manually calling `open()` and `close()`?**

### Short Interview Answer
"Using `with` guarantees the file gets closed automatically once the block finishes, even if an exception occurs inside it. If you manually call `open()` and `close()`, an error before the `close()` call would leave the file open, which can lead to resource leaks or data not being properly saved."

## 17.2 `pathlib`

### Definition
> `pathlib` is a modern, object-oriented module for working with file system paths, replacing many older `os.path` string-based operations.

### Simple Example
```python
from pathlib import Path

p = Path("data") / "file.txt"
print(p.exists())
print(p.suffix)      # ".txt"
print(p.parent)        # data
```

### Interview Question
**Q: Why is `pathlib` generally preferred over `os.path` in modern Python?**

### Short Interview Answer
"`pathlib` represents paths as objects instead of plain strings, so operations like joining paths, checking if a file exists, or getting the file extension are more readable and less error-prone. It also works consistently across operating systems, since it handles path separators internally."

## 17.3 JSON, CSV, and Serialization

### Definition
> JSON is a lightweight, text-based data format widely used for exchanging structured data. The `json` module converts between Python objects and JSON text (serialization/deserialization). `csv` handles comma-separated tabular data. `pickle` serializes Python objects into a binary format specific to Python.

### Easy Meaning
JSON and CSV are human-readable ways to save/share structured data. Pickle is a Python-only way to save almost any Python object exactly as it is, but it can't be read by other languages.

### Remember It
**JSON = universal, text-based. Pickle = Python-only, binary, can serialize almost any object.**

### Simple Example
```python
import json

data = {"name": "Ana", "age": 30}
json_str = json.dumps(data)      # Python object -> JSON string
print(json_str)

parsed = json.loads(json_str)     # JSON string -> Python object
print(parsed["name"])

import csv
with open("people.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "age"])
    writer.writerow(["Ana", 30])

import pickle
with open("data.pkl", "wb") as f:
    pickle.dump(data, f)
with open("data.pkl", "rb") as f:
    loaded = pickle.load(f)
```

### Important Differences: JSON vs Pickle

| Aspect | JSON | Pickle |
|---|---|---|
| Format | Text, human-readable | Binary |
| Cross-language | Yes | No — Python only |
| Security | Safe to load from untrusted sources (data-only) | **Unsafe to unpickle untrusted data — can execute arbitrary code** |
| Can serialize | Basic data types (dict, list, str, number, bool, None) | Almost any Python object |

### Common Interview Trap
**Wrong thinking:** "Pickle and JSON are interchangeable — just pick whichever is convenient."
**Correct thinking:** Never unpickle data from an untrusted source — pickle can execute arbitrary code during deserialization, making it a security risk. JSON is safe for data interchange, especially with external or untrusted sources.
**What to say in the interview:** "I'd only use pickle for trusted, internal Python-to-Python data, and use JSON whenever data might come from — or go to — an external or untrusted source."

### Interview Question
**Q: What's the difference between JSON and pickle in Python?**

### Short Interview Answer
"JSON is a text-based, language-independent format, good for exchanging data between different systems, but it only supports basic data types like dictionaries, lists, strings, and numbers. Pickle is Python-specific and can serialize almost any Python object into binary form, but it's not safe to use with untrusted data, since unpickling can execute arbitrary code."
