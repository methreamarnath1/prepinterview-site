# Chapter 18 — OOP Foundations

## 18.1 Classes, Objects, and Constructors

### Definition
> A class is a blueprint for creating objects, defining what data (attributes) and behavior (methods) those objects will have. An object is a specific instance created from that class. `__init__` is the constructor method that sets up a new object's initial state when it's created.

### Easy Meaning
A class is like a cookie cutter; objects are the actual cookies made from it. `__init__` is what happens the moment a new cookie is cut — setting its initial shape and ingredients.

### Remember It
**Class = blueprint. Object = instance made from that blueprint. `__init__` = setup code run at creation.**

### Simple Example
```python
class Dog:
    def __init__(self, name, breed):
        self.name = name
        self.breed = breed

    def bark(self):
        return f"{self.name} says Woof!"

my_dog = Dog("Rex", "Labrador")
print(my_dog.bark())   # "Rex says Woof!"
```

### Interview Question
**Q: What is a class, and what is `self`?**

### Short Interview Answer
"A class is a blueprint for creating objects — it defines the attributes and methods that its instances will have. `self` refers to the specific instance the method is being called on, which is how each object can access and modify its own data separately from other instances of the same class. Python passes `self` automatically when you call a method on an instance."

### Detailed Explanation
When you write `my_dog.bark()`, Python actually translates this internally to `Dog.bark(my_dog)` — the instance itself is passed as the first argument, conventionally named `self`. This is why every regular method definition includes `self` as its first parameter: it's how the method knows which specific object's data to work with. `__init__` isn't technically the object's creator (that's a different method, `__new__`, covered in Part 3) — it's the initializer, responsible for setting up the object's attributes right after it's been created.

## 18.2 Encapsulation

### Definition
> Encapsulation means bundling data and the methods that operate on it together inside a class, and controlling access to that data — often by convention, using a naming pattern to signal what should be treated as "private."

### Easy Meaning
Encapsulation means keeping an object's internal details protected and only exposing what's necessary to the outside world, similar to how a car's engine is hidden under the hood — you interact with the steering wheel and pedals, not the engine directly.

### Remember It
**`_name` = "internal, please don't touch" (convention only). `__name` = name-mangled, harder to access accidentally.**

### Simple Example
```python
class BankAccount:
    def __init__(self, balance):
        self._balance = balance          # convention: "protected"
        self.__pin = "1234"                 # name-mangled: "private-ish"

    def get_balance(self):
        return self._balance

acc = BankAccount(100)
print(acc._balance)          # accessible, but convention says "don't"
print(acc._BankAccount__pin)   # still accessible, just name-mangled
```

### Common Mistakes
- Believing a single or double underscore makes an attribute truly private/inaccessible — Python doesn't enforce real access restriction; it's convention plus name-mangling, not a hard security boundary.

### Interview Question
**Q: Does Python have true "private" variables like Java or C++?**

### Short Interview Answer
"Not really — Python relies on convention rather than strict enforcement. A single underscore prefix, like `_balance`, signals 'this is internal, please don't access it directly,' but nothing stops you from accessing it. A double underscore prefix, like `__pin`, triggers name mangling, which makes it harder to access accidentally from outside the class, but it's still technically reachable if you know the mangled name."

## 18.3 Inheritance, Polymorphism, Abstraction

### Definition
> Inheritance lets a class (child/subclass) reuse and extend the attributes and methods of another class (parent/superclass). Polymorphism means different classes can be used through the same interface, each responding to the same method call in its own way. Abstraction means hiding complex implementation details behind a simple interface.

### Easy Meaning
Inheritance = "borrow behavior from a parent class." Polymorphism = "different objects can respond to the same call in their own way." Abstraction = "show only what's necessary, hide the rest."

### Remember It
**Inheritance = reuse. Polymorphism = same call, different behavior. Abstraction = hide complexity.**

### Simple Example
```python
class Animal:
    def speak(self):
        raise NotImplementedError

class Dog(Animal):
    def speak(self):
        return "Woof!"

class Cat(Animal):
    def speak(self):
        return "Meow!"

for animal in [Dog(), Cat()]:
    print(animal.speak())   # Woof! then Meow! -- polymorphism in action
```

### Interview Question
**Q: What is polymorphism, with an example?**

### Short Interview Answer
"Polymorphism means objects of different classes can be treated through a common interface, and each responds to the same method call in its own specific way. For example, if `Dog` and `Cat` both have a `speak()` method, I can loop through a list of animals and call `.speak()` on each one, without needing to know exactly which subclass it is — each object automatically uses its own version of `speak()`."

### Interview Depth Levels
**Basic:** What is inheritance?
**Intermediate:** What's the difference between inheritance and polymorphism?
**Tricky:** Can polymorphism happen without inheritance in Python? *(Answer: Yes — Python uses duck typing, so any object with a matching method can be used polymorphically, even without a shared parent class, as long as it has the expected method.)*

### Quick Revision
- Definition: Class = blueprint, Object = instance, `__init__` = setup code.
- Encapsulation: `_x` = convention, `__x` = name-mangled, neither is truly private.
- Inheritance = reuse, Polymorphism = same call/different behavior, Abstraction = hide complexity.
- Remember: **Class = blueprint. Object = instance. Inheritance = reuse. Polymorphism = same call, different behavior.**
