# Chapter 2: Descriptors

> Continuity: builds on Ch.1 §1.3 (attribute lookup) and §1.5 (method binding — functions are descriptors).

### 2.1 What Is a Descriptor?

**Definition:** A descriptor is any object whose class defines `__get__`, `__set__`, or `__delete__`, and which is placed as a **class attribute**. When you access that attribute on an instance, Python routes the access through these methods instead of returning the object directly.

**Easy Meaning:** A descriptor is a class-level attribute that controls what happens when you read, write, or delete it.

**Remember It:** Descriptor = attribute with custom get/set/delete logic, defined once on the class, reused by every instance.

**Why It Exists:** Descriptors are the mechanism *underneath* `property`, methods, `staticmethod`, and `classmethod`. They let you write reusable validation/computation logic once instead of repeating it in every property.

### 2.2 Data Descriptors vs Non-Data Descriptors

| Type | Defines | Priority in lookup |
|---|---|---|
| Data descriptor | `__get__` **and** `__set__` (or `__delete__`) | Highest — overrides instance `__dict__` |
| Non-data descriptor | Only `__get__` | Lower — instance `__dict__` wins if the name also exists there |

This priority order is *why* instance attributes can override plain methods (non-data descriptors) but **cannot** override a `property` (data descriptor).

### 2.3 Syntax & Simple Example

```python
class PositiveNumber:
    def __set_name__(self, owner, name):
        self.name = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name)

    def __set__(self, obj, value):
        if value < 0:
            raise ValueError("must be positive")
        setattr(obj, self.name, value)

class Product:
    price = PositiveNumber()   # descriptor as class attribute
    def __init__(self, price):
        self.price = price

p = Product(10)
print(p.price)     # 10
p.price = -5        # raises ValueError
```

### 2.4 Realistic Example — Reusable Validation
Descriptors shine when the same validation is needed across many attributes/classes (e.g., an ORM field type, a typed config system) — write it once as a descriptor, reuse everywhere, instead of repeating `@property` boilerplate per field.

### 2.5 `property` Is Just a Data Descriptor
```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value < 0:
            raise ValueError("radius must be non-negative")
        self._radius = value
```
`property` implements `__get__`/`__set__` internally — it's a built-in data descriptor factory.

### 2.6 Common Mistakes
- Storing the value **directly on the descriptor instance** (`self.value = value` inside `__set__`) instead of on the owning object — this causes the value to be **shared across all instances**, since the descriptor object is a single class-level object.
- Forgetting `__set_name__` (Python 3.6+) to auto-derive the storage attribute name.

### 2.7 Predict the Output
```python
class Shared:
    def __get__(self, obj, objtype=None):
        return self.value
    def __set__(self, obj, value):
        self.value = value   # BUG: stored on descriptor, not obj

class Widget:
    x = Shared()

w1 = Widget()
w2 = Widget()
w1.x = 100
print(w2.x)
```
**Answer:** `100`
**Explanation:** Because the value is stored on the descriptor object itself (shared across the class), not per-instance, `w2.x` incorrectly reflects `w1`'s value.
**Interview Concept Tested:** Understanding that descriptors are class-level singletons — storage must be per-instance (usually via the instance's `__dict__`, keyed by a derived name).

### 2.8 Interview Question
**Q: What is a descriptor and how does `property` relate to it?**

**Short Interview Answer:** "A descriptor is an object that customizes attribute access by implementing `__get__`, `__set__`, or `__delete__`, and is defined at the class level. `property` is Python's built-in way of creating a data descriptor without writing a full descriptor class — it wires up getter/setter functions for you. Descriptors are also how bound methods work internally, since functions implement `__get__`."

### 2.9 Common Interview Trap
**Wrong thinking:** "Instance attributes always take priority over class attributes."
**Correct thinking:** Only for **non-data descriptors** and plain class attributes. A **data descriptor** on the class always wins over the instance `__dict__`.

### Quick Revision
- Descriptor = `__get__`/`__set__`/`__delete__` on a class attribute.
- Data descriptor (`__set__` present) beats instance `__dict__`; non-data descriptor loses to it.
- `property` = built-in data descriptor.
- Trap: storing state on `self` inside the descriptor (shares across instances) instead of on the owning object.
