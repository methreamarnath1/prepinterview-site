# Chapter 3: Decorators, Closures & Late Binding

### 3.1 Closures — Refresher + Deeper Behavior

**Definition:** A closure is a function that remembers the variables from its enclosing scope, even after that outer function has finished executing.

**How It Works (Internals):** Python doesn't copy the value — it keeps a **cell object** that references the variable. The inner function's `__closure__` attribute holds these cells. This is why closures can see changes to the outer variable that happen *after* the closure is created.

```python
def make_counter():
    count = 0
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

counter = make_counter()
print(counter())  # 1
print(counter())  # 2
print(counter.__closure__[0].cell_contents)  # 2
```

### 3.2 Late Binding Closures — THE Classic Trap

**Definition:** Late binding means a closure looks up a variable's value **at call time**, not at definition time. In a loop, all closures created in the loop share the *same* variable cell, so they all see its *final* value.

```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)

print([f() for f in funcs])   # [2, 2, 2] — NOT [0, 1, 2]
```
**Why:** All three lambdas share the same cell for `i`. By the time they're called, the loop has finished and `i == 2`.

**Fix — default argument trick (forces early binding):**
```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]
```

**Interview Question — Q: Why does this loop-with-lambda pattern print the same value for every function?**
**Short Interview Answer:** "Because closures in Python capture variables by reference, not by value. All the lambdas created in the loop share the same cell for the loop variable, so by the time they're called after the loop ends, they all see its final value. The common fix is to bind the value early using a default argument, like `lambda i=i: i`, since default argument values are evaluated once, at function-definition time."

### 3.3 What Is a Decorator?

**Definition:** A decorator is a callable that takes a function (or class) and returns a new function (or class), typically adding behavior before/after the original runs — without modifying the original's source code.

**Easy Meaning:** A decorator wraps your function in another function.

**Syntax:**
```python
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print("Before call")
        result = func(*args, **kwargs)
        print("After call")
        return result
    return wrapper

@my_decorator
def greet(name):
    return f"Hello {name}"

# Equivalent to: greet = my_decorator(greet)
```

### 3.4 `functools.wraps` — Why It's Necessary

**Problem:** Without it, the wrapper function replaces the original's `__name__`, `__doc__`, and signature — breaking introspection, debugging tools, and documentation generators.

```python
import functools

def my_decorator(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@my_decorator
def greet(name):
    """Greets a person."""
    return f"Hello {name}"

print(greet.__name__)  # "greet" (would be "wrapper" without functools.wraps)
print(greet.__doc__)   # "Greets a person."
```

### 3.5 Decorator Factories (Decorators with Arguments)

```python
def repeat(times):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            results = []
            for _ in range(times):
                results.append(func(*args, **kwargs))
            return results
        return wrapper
    return decorator

@repeat(times=3)
def say_hi():
    return "hi"

print(say_hi())  # ['hi', 'hi', 'hi']
```
**How it works:** `repeat(times=3)` returns `decorator`, which then wraps `say_hi` — three layers of function calls total: `repeat` → `decorator` → `wrapper`.

### 3.6 Class Decorators

A decorator can also wrap an entire class:
```python
def add_greeting(cls):
    cls.greet = lambda self: f"Hi, I'm {self.name}"
    return cls

@add_greeting
class Person:
    def __init__(self, name):
        self.name = name

print(Person("Amar").greet())  # "Hi, I'm Amar"
```

### 3.7 Class-Based Decorators (using `__call__`)

```python
class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)
        self.func = func
        self.calls = 0

    def __call__(self, *args, **kwargs):
        self.calls += 1
        return self.func(*args, **kwargs)

@CountCalls
def say_hello():
    return "hello"

say_hello()
say_hello()
print(say_hello.calls)  # 2
```

### 3.8 Common Mistakes
- Forgetting `functools.wraps` → broken introspection/debugging.
- Stacking decorators and being surprised by execution order — decorators apply **bottom-up**, but execute **top-down** at call time:
```python
@dec_a
@dec_b
def f(): ...
# equivalent to f = dec_a(dec_b(f))
# so dec_a's wrapper code runs FIRST when f() is called (outermost wraps innermost)
```

### 3.9 Predict the Output
```python
def decorator(func):
    print("Decorating")
    def wrapper():
        print("Calling")
        return func()
    return wrapper

@decorator
def hello():
    print("Hello")

print("---")
hello()
```
**Answer:**
```
Decorating
---
Calling
Hello
```
**Explanation:** The decorator's outer body (`print("Decorating")`) runs **immediately at definition time** (when `@decorator` is applied), not when `hello()` is later called. This trips up many candidates who expect all prints to appear only after the call.

**Interview Concept Tested:** Decoration happens at import/definition time, not call time.

### 3.10 Common Interview Trap
**Wrong thinking:** "The decorator's code runs when the decorated function is called."
**Correct thinking:** The **decorator function itself** runs immediately when the module loads / class body executes; only the **inner wrapper** runs on each call.

### Quick Revision
- Closures capture variables by reference (via cells), not by value → late binding trap in loops.
- `@decorator` sugar = `func = decorator(func)`, applied at definition time.
- Always use `functools.wraps` in wrapper functions.
- Decorator factories add a third layer: factory → decorator → wrapper.
- Stacked decorators: apply bottom-up, execute top-down.
