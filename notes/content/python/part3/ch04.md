# Chapter 4: Context Managers

### 4.1 What Is a Context Manager?

**Definition:** A context manager is an object that defines `__enter__` and `__exit__`, allowing it to be used with the `with` statement to guarantee setup and cleanup code runs — even if an exception occurs.

**Why It Exists:** Resources like files, locks, and network connections must be released reliably. `with` guarantees cleanup runs, replacing error-prone manual `try/finally` blocks.

### 4.2 Syntax & How It Works
```python
with open("file.txt") as f:
    data = f.read()
```
Internally:
1. `f = open("file.txt")` — actually calls `open(...).__enter__()`.
2. Block runs.
3. `open(...).__exit__(exc_type, exc_value, traceback)` is called **no matter what** — even if the block raised an exception.
4. If `__exit__` returns `True`, the exception is **suppressed**. If it returns `False`/`None`, the exception propagates normally.

### 4.3 Writing a Custom Context Manager (Class-Based)
```python
class Timer:
    def __enter__(self):
        import time
        self.start = time.time()
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        import time
        print(f"Elapsed: {time.time() - self.start:.4f}s")
        return False   # do not suppress exceptions

with Timer():
    sum(range(10**6))
```

### 4.4 `contextlib.contextmanager` — Generator-Based Context Managers
```python
from contextlib import contextmanager

@contextmanager
def timer():
    import time
    start = time.time()
    try:
        yield
    finally:
        print(f"Elapsed: {time.time() - start:.4f}s")

with timer():
    sum(range(10**6))
```
**How it works:** Code before `yield` = `__enter__` logic. Code after `yield` (in `finally`) = `__exit__` logic. The `try/finally` is essential — without it, an exception in the `with` block would skip the cleanup code.

### 4.5 Handling Exceptions Inside `__exit__`
```python
class SuppressValueError:
    def __enter__(self):
        return self
    def __exit__(self, exc_type, exc_value, traceback):
        if exc_type is ValueError:
            print("Suppressed a ValueError")
            return True   # suppress it
        return False

with SuppressValueError():
    raise ValueError("oops")
print("Execution continues here")
```
**Output:**
```
Suppressed a ValueError
Execution continues here
```

### 4.6 Other Useful `contextlib` Tools
- `contextlib.suppress(ExceptionType)` — suppress specific exceptions without writing a full try/except.
- `contextlib.closing(obj)` — ensures `obj.close()` is called, for objects that have `close()` but aren't full context managers.
- `contextlib.ExitStack()` — dynamically manage a variable number of context managers.

```python
from contextlib import suppress
with suppress(FileNotFoundError):
    open("missing.txt")
print("continues normally")
```

### 4.7 Common Mistakes
- Forgetting `try/finally` in a generator-based context manager — cleanup gets skipped if an exception occurs inside the `with` block.
- Returning `True` from `__exit__` unintentionally (e.g., forgetting an explicit `return False`) — silently swallows real bugs.
- Assuming `__enter__`'s return value is the context manager itself — it's whatever you explicitly return; `open()` returns the file object, but a custom class might return something else (or `self`).

### 4.8 Predict the Output
```python
class CM:
    def __enter__(self):
        print("enter")
        return self
    def __exit__(self, exc_type, exc_value, tb):
        print("exit")
        return True

with CM():
    print("inside")
    raise ValueError("boom")
print("after")
```
**Answer:**
```
enter
inside
exit
after
```
**Explanation:** `__exit__` returns `True`, which suppresses the `ValueError` — execution continues normally after the `with` block, as if nothing was raised.

**Interview Concept Tested:** The suppress-via-return-True mechanism of `__exit__`.

### 4.9 Interview Question
**Q: What is the purpose of the `with` statement and how does it guarantee cleanup?**

**Short Interview Answer:** "The `with` statement works with any object implementing the context manager protocol — `__enter__` and `__exit__`. `__enter__` runs at the start of the block and its return value is bound to the `as` variable. `__exit__` is guaranteed to run when the block ends, whether it ended normally or via an exception, which makes it perfect for cleanup like closing files or releasing locks. If `__exit__` returns `True`, it can even suppress the exception."

### Quick Revision
- `__enter__` runs at block start; `__exit__` always runs at block end (even on exception).
- `__exit__` returning `True` suppresses the exception.
- `contextlib.contextmanager` turns a generator into a context manager — code before `yield` is enter, code after (in `finally`) is exit.
- `contextlib.suppress`, `closing`, `ExitStack` are common utilities.
- Trap: forgetting `try/finally` in generator-based managers skips cleanup on exceptions.
