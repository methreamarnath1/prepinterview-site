# Chapter 5: Memory Management

### 5.1 Reference Counting (CPython Implementation Detail)

**Definition:** CPython keeps a count, on every object, of how many references point to it. When the count drops to zero, the object's memory is immediately freed.

```python
import sys
a = []
print(sys.getrefcount(a))  # includes the temporary ref from getrefcount's own argument
b = a
print(sys.getrefcount(a))  # increased by 1, since b also points to it
del b
print(sys.getrefcount(a))  # decreased back
```

**PYTHON LANGUAGE GUARANTEE vs CPYTHON DETAIL:** Reference counting is a **CPython implementation detail**, not a language guarantee. Other implementations (PyPy) use different garbage collection strategies entirely and don't free objects the instant refcount hits zero.

### 5.2 Garbage Collection & Cyclic References

**Why refcounting alone isn't enough:** Two objects can reference each other in a cycle, keeping each other's refcount above zero forever, even if nothing external points to either.

```python
import gc

class Node:
    def __init__(self):
        self.other = None

a = Node()
b = Node()
a.other = b
b.other = a   # cycle!
del a, b       # refcounts don't hit zero — cycle keeps them alive
gc.collect()   # the cyclic garbage collector finds and frees the cycle
```

**How it works internally:** CPython runs a generational cyclic garbage collector alongside refcounting. It periodically scans container objects (lists, dicts, class instances) that could form cycles, and frees groups of objects that are unreachable from outside the group — even if their mutual refcounts are nonzero.

### 5.3 `weakref` — References That Don't Keep Objects Alive

```python
import weakref

class Resource:
    pass

r = Resource()
weak = weakref.ref(r)
print(weak())     # <Resource object> — still alive
del r
print(weak())      # None — object was collected, weak reference doesn't prevent it
```
**Why It's Used:** Caches, observer patterns, and parent↔child relationships where you don't want the reference itself to keep an object alive (avoiding memory leaks from unintentional cycles).

### 5.4 `__del__` — Object Finalization

**Definition:** `__del__` is called just before an object's memory is reclaimed.

**Common Mistakes:**
- Assuming `__del__` runs immediately when you call `del obj` — `del` only removes the *name binding*; the object is freed (and `__del__` called) only when the refcount hits zero, which might be immediately or might be later (or never, if a cycle keeps it alive until GC runs — and objects with `__del__` in a cycle used to be genuinely uncollectable in old Python versions; modern Python resolves this, but it's still fragile).
- Relying on `__del__` for critical cleanup (like closing a database connection) — use a context manager instead, since `__del__`'s timing is not guaranteed.

### 5.5 Shallow Copy vs Deep Copy

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

shallow[0].append(99)
print(original)  # [[1, 2, 99], [3, 4]] — inner list is SHARED
print(deep)       # unaffected — deep copy recursively copied inner lists too
```

| Aspect | Shallow Copy | Deep Copy |
|---|---|---|
| Top-level container | New object | New object |
| Nested objects | Shared with original | Recursively copied |
| Speed | Faster | Slower |
| Use case | Flat structures | Nested/mutable structures |

### 5.6 `__slots__`

**Definition:** `__slots__` is a class-level declaration that tells Python to allocate fixed storage for a specific set of attributes instead of creating a per-instance `__dict__`.

```python
class Point:
    __slots__ = ("x", "y")
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
p.z = 5   # AttributeError — not in __slots__, and there's no __dict__ to fall back on
```

**Why It's Used:** Saves significant memory (no per-instance dict) and slightly speeds up attribute access — valuable when creating millions of small objects.

**Common Mistakes:**
- Assuming `__slots__` also restricts subclasses — a subclass without its own `__slots__` gets a `__dict__` again, defeating the purpose.
- Trying to add class-level default values that conflict with slot descriptors.

### 5.7 Interning & Integer Caching (CPython Implementation Details)

**Small integer caching:** CPython pre-creates and reuses integers from **-5 to 256**.
```python
a = 100
b = 100
print(a is b)   # True — small int cache

x = 1000
y = 1000
print(x is y)   # Often False — outside the cached range (implementation/version dependent)
```

**String interning:** CPython automatically interns string literals that look like identifiers (and always interns string constants used internally).
```python
a = "hello"
b = "hello"
print(a is b)   # Often True — interned literal

c = "hello world!"
d = "hello world!"
print(c is d)   # NOT guaranteed — may be False, especially with spaces/special chars
```

**CRITICAL WARNING for interviews:** Never rely on `is` for value comparison of ints/strings in real code — always use `==`. The caching behavior above is a CPython optimization detail, not a language guarantee, and can differ between Python versions or implementations.

### 5.8 Predict the Output
```python
a = 256
b = 256
print(a is b)      # True (cached)

a = 257
b = 257
print(a is b)      # commonly False, but NOT guaranteed by the language
```
**Interview Concept Tested:** Distinguishing `is` (identity) from `==` (value), and knowing integer caching is an implementation detail, not something to depend on.

### 5.9 Common Interview Trap
**Wrong thinking:** "`is` and `==` behave the same for numbers and strings."
**Correct thinking:** `==` checks value equality (`__eq__`); `is` checks object identity. They coincide for small cached ints/interned strings *by accident of implementation*, not by guarantee.

### Quick Revision
- CPython uses refcounting + generational cyclic GC.
- `weakref` doesn't keep objects alive — useful for caches.
- `__del__` timing is not guaranteed — don't use for critical cleanup.
- Shallow copy shares nested objects; deep copy recursively duplicates them.
- `__slots__` removes per-instance `__dict__`, saving memory but restricting dynamic attributes.
- Small-int caching (-5 to 256) and string interning are CPython details — never rely on `is` for value equality.
