# Chapter 6: Introspection & Metaclasses

### 6.1 Introspection Built-ins

| Function | Purpose |
|---|---|
| `dir(obj)` | Lists names in the object's namespace |
| `vars(obj)` | Returns `obj.__dict__` |
| `getattr(obj, name, default)` | Gets an attribute dynamically, with optional default |
| `setattr(obj, name, value)` | Sets an attribute dynamically |
| `hasattr(obj, name)` | Checks if attribute access would succeed |
| `isinstance(obj, cls)` | Checks if `obj` is an instance of `cls` (or subclass) |
| `issubclass(cls1, cls2)` | Checks class hierarchy relationship |
| `callable(obj)` | Checks if `obj` can be called (has `__call__`) |
| `type(obj)` | Returns the object's class |

```python
class Person:
    def __init__(self, name):
        self.name = name

p = Person("Amar")
print(hasattr(p, "name"))          # True
print(getattr(p, "age", "N/A"))    # "N/A" — attribute doesn't exist
setattr(p, "age", 21)
print(vars(p))                      # {'name': 'Amar', 'age': 21}
```

**Common Mistake:** Using `hasattr` and assuming it only checks existence — it actually tries the attribute access and catches `AttributeError`. If your `__getattr__` raises a *different* exception, `hasattr` won't catch it and will propagate the error instead of returning `False`.

### 6.2 `type()` — The Root of Class Creation

**Key Insight:** `type` is both the built-in function that reports an object's class, AND the default **metaclass** — the class that creates all ordinary classes.

```python
print(type(5))         # <class 'int'>
print(type(int))       # <class 'type'>
print(type(type))      # <class 'type'> — type is its own metaclass
```

`class Foo: pass` is really syntactic sugar for calling `type()` directly:
```python
Foo = type("Foo", (), {})   # name, bases, namespace dict
f = Foo()
```

### 6.3 What Is a Metaclass?

**Definition:** A metaclass is "the class of a class" — it controls how classes themselves are created, just as a class controls how instances are created.

**Easy Meaning:** If a class is a blueprint for objects, a metaclass is a blueprint for classes.

**Remember It:** Metaclass = a factory that builds classes, the same way a class is a factory that builds instances.

**Why It's Used:** Metaclasses let you customize class creation itself — validating class definitions, auto-registering subclasses, enforcing coding standards, or building ORMs/frameworks (e.g., Django models use a metaclass to turn field declarations into database schema).

### 6.4 Writing a Metaclass

```python
class UpperAttrMeta(type):
    def __new__(mcs, name, bases, namespace):
        uppercase_attrs = {
            key.upper() if not key.startswith("__") else key: value
            for key, value in namespace.items()
        }
        return super().__new__(mcs, name, bases, uppercase_attrs)

class Demo(metaclass=UpperAttrMeta):
    greeting = "hello"

print(Demo.GREETING)   # "hello" — attribute name was uppercased at class-creation time
```

**How it works — the class-creation pipeline:**
1. Python collects the class body into a namespace dictionary.
2. Calls `metaclass.__prepare__(name, bases)` first (optional) — returns the namespace mapping to use while executing the class body (lets you use an `OrderedDict` or custom mapping instead of a plain dict).
3. Executes the class body inside that namespace.
4. Calls `metaclass.__new__(mcs, name, bases, namespace)` to create the class object.
5. Calls `metaclass.__init__(cls, name, bases, namespace)` to initialize it.

### 6.5 `__prepare__`

```python
class OrderTrackingMeta(type):
    @classmethod
    def __prepare__(mcs, name, bases):
        print("Preparing namespace")
        return {}   # could return an OrderedDict-like object for special ordering

class Demo(metaclass=OrderTrackingMeta):
    x = 1
```

### 6.6 Metaclass `__new__` vs `__init__`

Same distinction as instance-level `__new__`/`__init__` (Ch.1 §1.2), but one level up:
- Metaclass `__new__(mcs, name, bases, namespace)` — creates the **class object**.
- Metaclass `__init__(cls, name, bases, namespace)` — initializes the **class object** after creation.

### 6.7 Common Mistakes
- Confusing inheriting from a class vs using it as a metaclass — `class Foo(Base):` makes `Base` a parent class; `class Foo(metaclass=Meta):` makes `Meta` the metaclass.
- Overusing metaclasses for problems solvable with simpler tools (class decorators, `__init_subclass__`) — metaclasses are powerful but reduce readability; most "metaclass" needs in modern Python can be solved with `__init_subclass__` instead.

### 6.8 Interview Question
**Q: What is a metaclass and when would you use one?**

**Short Interview Answer:** "A metaclass is the class that creates classes — the default metaclass in Python is `type`. Just like a class defines how its instances behave, a metaclass defines how classes themselves are constructed. I'd use a metaclass when I need to customize class creation itself, like auto-registering every subclass in a plugin system, or validating that certain methods are implemented at class-definition time rather than at instantiation. In practice, metaclasses are powerful but rarely needed — many use cases can be solved more simply with class decorators or `__init_subclass__`."

### 6.9 Predict the Output
```python
class Meta(type):
    def __new__(mcs, name, bases, namespace):
        print(f"Creating class: {name}")
        return super().__new__(mcs, name, bases, namespace)

class A(metaclass=Meta):
    pass

class B(A):
    pass
```
**Answer:**
```
Creating class: A
Creating class: B
```
**Explanation:** Since `B` inherits from `A`, and `A`'s metaclass is `Meta`, `B` automatically also uses `Meta` as its metaclass (metaclasses are inherited), so `Meta.__new__` runs for both class creations.

**Interview Concept Tested:** Metaclasses propagate down the inheritance chain automatically.

### 6.10 Common Interview Trap
**Wrong thinking:** "A metaclass only affects the class it's directly assigned to."
**Correct thinking:** All subclasses inherit the metaclass, unless a conflict forces Python to compute a more derived metaclass (or raises `TypeError` if metaclasses are incompatible).

### Quick Revision
- `type` is both a function (reports class) and the default metaclass.
- Metaclass controls class *creation*, class controls instance creation.
- Pipeline: `__prepare__` → body execution → metaclass `__new__` → metaclass `__init__`.
- Metaclasses are inherited by subclasses.
- Prefer `__init_subclass__` or class decorators unless you specifically need metaclass power.
