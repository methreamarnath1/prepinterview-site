# Chapter 7: Advanced Generators

> Refresher continuity: Part 2 covered basic generators and `yield`. This chapter covers the full generator protocol used for coroutine-style communication.

### 7.1 `send()` — Sending Values Into a Generator

**Definition:** `generator.send(value)` resumes the generator and makes `value` become the result of the `yield` expression that paused it.

```python
def echo():
    while True:
        received = yield
        print(f"Received: {received}")

gen = echo()
next(gen)          # "priming" — must advance to the first yield before sending
gen.send("hello")  # Received: hello
gen.send("world")  # Received: world
```

**Common Mistake:** Calling `.send()` before priming the generator with `next()` (or an initial `.send(None)`) — raises `TypeError: can't send non-None value to a just-started generator`.

### 7.2 `throw()` — Injecting an Exception

```python
def resilient():
    try:
        while True:
            yield "running"
    except ValueError:
        yield "caught ValueError, recovering"

gen = resilient()
print(next(gen))              # "running"
print(gen.throw(ValueError))  # "caught ValueError, recovering"
```
**How it works:** `throw()` raises the given exception *at the point where the generator is currently paused* (inside the `yield` expression), allowing the generator to catch and handle it internally.

### 7.3 `close()` and `GeneratorExit`

```python
def managed():
    try:
        yield "working"
    finally:
        print("Cleanup ran")

gen = managed()
next(gen)
gen.close()   # raises GeneratorExit inside the generator at the paused point
```
**Output:**
```
Cleanup ran
```

**How it works:** `close()` raises `GeneratorExit` inside the generator. If the generator catches it and then `yield`s again, Python raises `RuntimeError` (a generator must not yield after being asked to close). If the generator lets `GeneratorExit` propagate (typically via a `finally` block for cleanup), it exits cleanly.

### 7.4 `yield from` — Delegating to a Sub-generator

```python
def inner():
    yield 1
    yield 2
    return "inner done"

def outer():
    result = yield from inner()
    print(f"inner returned: {result}")
    yield 3

for val in outer():
    print(val)
```
**Output:**
```
1
2
inner returned: inner done
3
```
**Why It's Used:** `yield from` transparently forwards `send()`, `throw()`, and `close()` calls to the sub-generator too — manually re-implementing this delegation with a plain loop is tedious and error-prone; `yield from` handles it correctly in one line.

### 7.5 Generators Are Iterators — the Protocol Recap
A generator automatically implements:
- `__iter__` (returns itself)
- `__next__` (resumes execution until the next `yield` or `StopIteration`)

```python
def gen():
    yield 1

g = gen()
print(iter(g) is g)   # True — generators are their own iterators
```

### 7.6 Predict the Output
```python
def counter():
    n = 0
    while True:
        step = yield n
        n += step if step else 1

c = counter()
print(next(c))       # 0 (priming, step is None first time, default +1 doesn't apply yet)
print(c.send(5))      # n += 5 -> 5
print(c.send(None))   # step is None -> n += 1 -> 6
```
**Answer:**
```
0
5
6
```
**Explanation:** The first `next()` primes the generator and returns the initial `yield n` value (`0`). `c.send(5)` resumes execution, `step` becomes `5`, `n` becomes `5`, and the loop yields it. `c.send(None)` makes `step` falsy, so the `else` branch (`+1`) applies.

**Interview Concept Tested:** Understanding exactly how `.send()` values become the result of the `yield` expression, and generator priming.

### 7.7 Common Interview Trap
**Wrong thinking:** "You can call `.send(value)` on a freshly created generator right away."
**Correct thinking:** A generator must first be advanced to its first `yield` (via `next()` or `send(None)`) before a non-`None` value can be sent.

### Quick Revision
- `send(value)`: resumes generator, `value` becomes the `yield` expression's result.
- `throw(exc)`: raises `exc` at the paused `yield` point.
- `close()`: raises `GeneratorExit`; generator should clean up via `finally`, not re-yield.
- `yield from`: delegates iteration AND forwards `send`/`throw`/`close` to a sub-generator.
- Trap: must prime a generator before sending a non-`None` value.
