# Chapter 8: Type Hints & Modern Typing

### 8.1 What Are Type Hints?

**Definition:** Type hints are optional annotations that document the expected types of variables, function parameters, and return values. Python does **not** enforce them at runtime by default — they exist for static analysis tools (mypy, pyright), IDEs, and readability.

**Remember It:** Type hints are documentation with tooling support, not runtime enforcement.

```python
def add(a: int, b: int) -> int:
    return a + b

add("2", "3")   # No error at runtime! Type hints are NOT enforced by Python itself.
```

### 8.2 Basic Typing Syntax

```python
from typing import List, Dict, Optional, Union, Tuple

def process(items: List[int]) -> Dict[str, int]:
    ...

def find(name: str) -> Optional[str]:   # str or None
    ...

def parse(value: Union[int, str]) -> None:
    ...

# Modern syntax (Python 3.9+/3.10+) avoids importing List/Dict:
def process_modern(items: list[int]) -> dict[str, int]:
    ...

def find_modern(name: str) -> str | None:   # PEP 604 union syntax
    ...
```

### 8.3 Generics

**Definition:** A generic type is parameterized by another type, letting you write reusable, type-safe containers/functions.

```python
from typing import TypeVar, Generic

T = TypeVar("T")

class Stack(Generic[T]):
    def __init__(self) -> None:
        self._items: list[T] = []

    def push(self, item: T) -> None:
        self._items.append(item)

    def pop(self) -> T:
        return self._items.pop()

int_stack: Stack[int] = Stack()
int_stack.push(5)
```

### 8.4 Protocols — Structural Typing

**Definition:** A `Protocol` defines an interface based on **structure** (what methods/attributes an object has) rather than **inheritance** — this is "duck typing," made explicit and checkable.

```python
from typing import Protocol

class Sized(Protocol):
    def __len__(self) -> int: ...

def show_length(obj: Sized) -> None:
    print(len(obj))

show_length([1, 2, 3])   # works — list has __len__, no inheritance from Sized needed
```
**Why It's Used:** Lets static type checkers verify "quacks like a duck" code without forcing classes into an explicit inheritance hierarchy.

### 8.5 `TypedDict`

**Definition:** `TypedDict` describes a dictionary with a fixed set of keys and specific value types for each key — useful for JSON-like structures.

```python
from typing import TypedDict

class Movie(TypedDict):
    title: str
    year: int

m: Movie = {"title": "Inception", "year": 2010}
```

### 8.6 `TypeGuard`

**Definition:** `TypeGuard` lets a function narrow a type for the type checker, based on a runtime check.

```python
from typing import TypeGuard

def is_str_list(val: list) -> TypeGuard[list[str]]:
    return all(isinstance(x, str) for x in val)

def process(items: list):
    if is_str_list(items):
        # type checker now knows items is list[str] here
        print(", ".join(items))
```

### 8.7 Common Mistakes
- Believing type hints raise `TypeError` at runtime — they don't, unless you use a separate validation library (like `pydantic`) or manually check.
- Using mutable default arguments and thinking type hints prevent the classic mutable-default-argument bug — they don't; that's a runtime semantics issue, unrelated to typing.
- Forgetting `from __future__ import annotations` (or Python 3.10+ default) when using newer union syntax (`X | Y`) on older Python versions.

### 8.8 Interview Question
**Q: Does Python enforce type hints at runtime?**

**Short Interview Answer:** "No. Python's type hints are purely optional annotations meant for static analysis tools like mypy, IDEs, and documentation. Python itself never checks them during execution — a function annotated to take an `int` will still happily accept a `str` at runtime, and no error is raised. If runtime enforcement is needed, you'd typically use a library like `pydantic` or add explicit `isinstance` checks."

### 8.9 Predict the Output
```python
def greet(name: int) -> str:
    return f"Hello, {name}"

print(greet("Amar"))
```
**Answer:** `Hello, Amar`
**Explanation:** Even though `name` is annotated as `int`, Python performs no runtime type checking — the function executes normally with a string argument.
**Interview Concept Tested:** Type hints are not enforced at runtime — a very commonly tested fact.

### Quick Revision
- Type hints are documentation/tooling aids, not runtime checks.
- `Generic`/`TypeVar` = type-parameterized reusable classes.
- `Protocol` = structural typing (duck typing made explicit for checkers).
- `TypedDict` = typed dict shape. `TypeGuard` = custom type-narrowing functions.
- Trap: assuming annotated types are enforced by the interpreter.
