# Chapter 9: Regex & datetime

### 9.1 The `re` Module — Core Functions

| Function | Purpose |
|---|---|
| `re.match()` | Matches only at the **start** of the string |
| `re.search()` | Finds the **first** match anywhere in the string |
| `re.findall()` | Returns **all** non-overlapping matches as a list |
| `re.finditer()` | Returns an iterator of match objects |
| `re.sub()` | Substitutes matches with replacement text |
| `re.split()` | Splits a string by a pattern |
| `re.compile()` | Precompiles a pattern for reuse (faster for repeated use) |

```python
import re

text = "Contact: amar@example.com, backup: help@test.org"
emails = re.findall(r"[\w.]+@[\w.]+", text)
print(emails)   # ['amar@example.com', 'help@test.org']

print(re.sub(r"\d+", "#", "Room 42, Floor 7"))   # "Room #, Floor #"
```

### 9.2 `match()` vs `search()` — Common Confusion
```python
re.match(r"World", "Hello World")    # None — match() only checks from position 0
re.search(r"World", "Hello World")   # matches — search() scans the whole string
```

### 9.3 Common Regex Building Blocks
- `\d` digit, `\w` word char, `\s` whitespace
- `+` one or more, `*` zero or more, `?` zero or one
- `()` groups, `(?:...)` non-capturing group
- `^` start, `$` end
- `.` any character (except newline, unless `re.DOTALL`)

### 9.4 Named Groups
```python
m = re.search(r"(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})", "2026-08-15")
print(m.group("year"))   # "2026"
print(m.groupdict())     # {'year': '2026', 'month': '08', 'day': '15'}
```

### 9.5 Common Mistakes
- Forgetting to use raw strings (`r"..."`) — without `r`, `\d` might be interpreted as an (invalid) escape sequence in some patterns, causing bugs or `DeprecationWarning`.
- Using `re.match()` when `re.search()` was intended, and being confused why an obviously-present substring "doesn't match."
- Not compiling patterns used repeatedly in a loop — hurts performance at scale.

### 9.6 The `datetime` Module

```python
from datetime import datetime, date, timedelta, timezone

now = datetime.now()
today = date.today()

# Formatting
print(now.strftime("%Y-%m-%d %H:%M:%S"))

# Parsing
parsed = datetime.strptime("2026-08-15", "%Y-%m-%d")

# Arithmetic
tomorrow = today + timedelta(days=1)

# Timezone-aware datetime
utc_now = datetime.now(timezone.utc)
```

**Key Interview Distinction — Naive vs Aware datetimes:**

| Type | Has timezone info? | Comparable across timezones? |
|---|---|---|
| Naive | No | Not reliably — assumes implicit local context |
| Aware | Yes (`tzinfo` set) | Yes — correctly accounts for offsets |

```python
naive = datetime.now()
aware = datetime.now(timezone.utc)
naive == aware   # TypeError: can't compare offset-naive and offset-aware datetimes
```

### 9.7 Common Interview Trap
**Wrong thinking:** "All `datetime` objects can be compared directly."
**Correct thinking:** Comparing a naive datetime with an aware one raises `TypeError` — you must ensure both are the same "kind" (both naive, or both timezone-aware) before comparing.

### 9.8 Predict the Output
```python
import re
result = re.findall(r"\d+", "a1b22c333")
print(result)
```
**Answer:** `['1', '22', '333']`
**Explanation:** `findall` returns every non-overlapping match of one-or-more digits as separate strings.

### Quick Revision
- `match()` = start only, `search()` = anywhere, `findall()` = all matches.
- Always use raw strings for regex patterns.
- `strftime` formats, `strptime` parses.
- Naive vs aware datetimes cannot be compared directly — trap.
