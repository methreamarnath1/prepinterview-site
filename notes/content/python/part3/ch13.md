# Chapter 13: Concurrency III — asyncio

### 13.1 What Is asyncio?

**Definition:** `asyncio` is Python's framework for writing **single-threaded concurrent** code using coroutines, driven by an event loop that switches between tasks whenever one is waiting (typically on I/O).

**Easy Meaning:** Instead of using multiple threads or processes, asyncio uses **one thread** that cooperatively juggles many tasks — whenever a task hits an `await` and starts waiting, the event loop runs a different ready task.

### 13.2 Coroutines — `async def` / `await`

```python
import asyncio

async def say_hello():
    print("Hello")
    await asyncio.sleep(1)   # yields control back to the event loop while "waiting"
    print("World")

asyncio.run(say_hello())
```
**Key Point:** Calling `say_hello()` does **not** run the function — it creates a coroutine object. The coroutine only actually executes when awaited or scheduled on the event loop (e.g., via `asyncio.run()`).

```python
coro = say_hello()
print(coro)   # <coroutine object say_hello at ...> — hasn't run yet!
```

### 13.3 The Event Loop

**How It Works:**
1. The event loop maintains a queue of ready tasks.
2. It runs a task until that task hits an `await` on something not yet ready (like a sleep timer or network response).
3. At that point, it pauses that task and runs another ready task.
4. When the awaited thing completes, the paused task becomes ready again and eventually resumes.

This is why asyncio gives **concurrency, not parallelism** — only one coroutine's code executes at any literal instant, but many can be "in flight" (waiting on I/O) simultaneously.

### 13.4 Running Multiple Coroutines Concurrently — `gather`

```python
import asyncio
import time

async def fetch(name, delay):
    print(f"Start {name}")
    await asyncio.sleep(delay)
    print(f"Done {name}")
    return f"{name} result"

async def main():
    start = time.time()
    results = await asyncio.gather(
        fetch("A", 2),
        fetch("B", 1),
        fetch("C", 3),
    )
    print(results)
    print(f"Total time: {time.time() - start:.1f}s")

asyncio.run(main())
```
**Output (approx):**
```
Start A
Start B
Start C
Done B
Done A
Done C
['A result', 'B result', 'C result']
Total time: 3.0s
```
**Why total time is ~3s, not ~6s:** All three coroutines run concurrently — while one sleeps, the others make progress. Total time equals the *longest* individual wait, not the sum.

### 13.5 Tasks and Futures

**`asyncio.create_task()`:** Schedules a coroutine to run on the event loop *immediately* (concurrently with other tasks), returning a `Task` (a subclass of `Future`) you can await later.

```python
async def main():
    task1 = asyncio.create_task(fetch("A", 2))
    task2 = asyncio.create_task(fetch("B", 1))
    # both are now running concurrently in the background
    result1 = await task1
    result2 = await task2
```

**Difference from just `await coro()` directly:** Awaiting a coroutine directly runs it to completion before moving to the next line. `create_task()` schedules it to start running *now*, letting you do other things before awaiting its result.

### 13.6 Cancellation
```python
async def long_task():
    try:
        await asyncio.sleep(10)
    except asyncio.CancelledError:
        print("Task was cancelled — cleaning up")
        raise   # best practice: re-raise after cleanup

async def main():
    task = asyncio.create_task(long_task())
    await asyncio.sleep(1)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("Confirmed cancelled")
```

### 13.7 Async Iterators and Async Generators

```python
class AsyncCounter:
    def __init__(self, limit):
        self.limit = limit
        self.count = 0

    def __aiter__(self):
        return self

    async def __anext__(self):
        if self.count >= self.limit:
            raise StopAsyncIteration
        await asyncio.sleep(0.1)
        self.count += 1
        return self.count

async def main():
    async for num in AsyncCounter(3):
        print(num)
```

**Async generator (simpler, using `yield`):**
```python
async def async_range(n):
    for i in range(n):
        await asyncio.sleep(0.1)
        yield i

async def main():
    async for val in async_range(3):
        print(val)
```

### 13.8 Async Context Managers

```python
class AsyncResource:
    async def __aenter__(self):
        print("Acquiring resource")
        await asyncio.sleep(0.1)
        return self

    async def __aexit__(self, exc_type, exc, tb):
        print("Releasing resource")
        await asyncio.sleep(0.1)

async def main():
    async with AsyncResource() as res:
        print("Using resource")
```

### 13.9 Common Mistakes
- Calling a coroutine function and forgetting to `await` it — this silently creates a coroutine object that never runs, with only a `RuntimeWarning: coroutine was never awaited`.
- Using `time.sleep()` instead of `await asyncio.sleep()` inside a coroutine — `time.sleep()` **blocks the entire event loop**, freezing every other task, defeating the purpose of asyncio.
- Mixing blocking (CPU-bound or blocking I/O) code directly inside coroutines without offloading it (e.g., via `loop.run_in_executor`) — a single blocking call can stall the whole event loop.

### 13.10 Predict the Output
```python
import asyncio

async def task(name, delay):
    await asyncio.sleep(delay)
    print(name)

async def main():
    await asyncio.gather(task("first", 2), task("second", 1))

asyncio.run(main())
```
**Answer:**
```
second
first
```
**Explanation:** Both coroutines start "simultaneously" via `gather`, but `task("second", 1)` finishes its shorter sleep first, so it prints before `task("first", 2)`.
**Interview Concept Tested:** `asyncio.gather` runs coroutines concurrently; completion order depends on their actual wait times, not the order they were listed.

### 13.11 Comparison — Threading vs Multiprocessing vs asyncio

| Aspect | Threading | Multiprocessing | asyncio |
|---|---|---|---|
| Parallelism | No (GIL) | Yes (separate processes) | No (single thread) |
| Best for | I/O-bound | CPU-bound | I/O-bound, high concurrency (many connections) |
| Overhead | Low-medium | High | Very low |
| Shared state | Shared memory (needs locks) | Separate memory (needs IPC) | Shared memory (single thread, no locks needed for pure async code) |
| Switching model | Preemptive (OS-driven) | Preemptive (OS-driven, separate processes) | Cooperative (`await` points) |

### 13.12 Interview Question
**Q: How is asyncio's concurrency different from threading's concurrency?**

**Short Interview Answer:** "asyncio achieves concurrency using a single thread and an event loop that cooperatively switches between coroutines at `await` points, whereas threading uses multiple OS threads that the operating system preemptively switches between. Because asyncio is single-threaded, it avoids most race conditions that come from shared mutable state, but it also means a single blocking call — like `time.sleep()` instead of `await asyncio.sleep()` — can freeze the entire event loop, which isn't a problem with threading. asyncio tends to scale better than threading for very high numbers of concurrent I/O-bound connections."

### 13.13 Common Interview Trap
**Wrong thinking:** "asyncio makes code run in parallel like multiprocessing."
**Correct thinking:** asyncio provides **concurrency** (interleaved progress) on a **single thread**, not **parallelism** (simultaneous execution) — for true parallel CPU work, you need multiprocessing.

### Quick Revision
- Coroutines (`async def`) must be awaited/scheduled to actually run.
- Event loop = cooperative scheduler, switches at `await` points.
- `gather()` runs coroutines concurrently; `create_task()` schedules immediately.
- `async for`/`__anext__`/`__aiter__`: async iteration protocol. `async with`/`__aenter__`/`__aexit__`: async context managers.
- Trap #1: forgetting to `await` a coroutine.
- Trap #2: using blocking calls (`time.sleep`) inside async code freezes the whole event loop.
- asyncio = concurrency via single-thread cooperative switching, NOT parallelism.
