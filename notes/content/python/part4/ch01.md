## Chapter 1: Core Data & Math Utilities

### 1.1 `collections` Module

**`Counter`** — counts hashable items.
```python
from collections import Counter
c = Counter("mississippi")
print(c)                 # Counter({'i': 4, 's': 4, 'p': 2, 'm': 1})
print(c.most_common(2))  # [('i', 4), ('s', 4)]
```
**Interview Q: How would you find the most frequent element in a list without writing manual loops?**
**Answer:** "Use `collections.Counter` — it builds a frequency dictionary in one pass, and `most_common(n)` gives the top n items by count directly."

**`defaultdict`** — auto-initializes missing keys.
```python
from collections import defaultdict
groups = defaultdict(list)
for word in ["apple", "ant", "banana"]:
    groups[word[0]].append(word)
print(dict(groups))   # {'a': ['apple', 'ant'], 'b': ['banana']}
```
**Trap:** Accessing a missing key with `defaultdict` **creates** that key (with the default value) as a side effect — unlike a plain dict's `.get()`.

**`deque`** — double-ended queue, O(1) appends/pops from both ends (vs O(n) for `list.insert(0, ...)`).
```python
from collections import deque
dq = deque([1, 2, 3])
dq.appendleft(0)
dq.append(4)
print(dq)          # deque([0, 1, 2, 3, 4])
dq.rotate(1)
print(dq)          # deque([4, 0, 1, 2, 3])
```
**Interview Q: Why use `deque` instead of `list` for a queue?**
**Answer:** "`list.pop(0)` is O(n) because every remaining element shifts. `deque` is implemented as a doubly linked list of blocks, giving O(1) append/pop from both ends — ideal for queues, sliding windows, and BFS."

**`namedtuple`** — lightweight, immutable, attribute-accessible tuple.
```python
from collections import namedtuple
Point = namedtuple("Point", ["x", "y"])
p = Point(1, 2)
print(p.x, p[0])   # 1 1
```

**`OrderedDict`** — dict with guaranteed order-sensitive equality and `move_to_end()`. Since Python 3.7, regular `dict` preserves insertion order too, but `OrderedDict` still differs: it's equality-order-sensitive (`OrderedDict([('a',1),('b',2)]) != OrderedDict([('b',2),('a',1)])`, while equivalent plain dicts ARE equal regardless of order), and offers `move_to_end()`.

### 1.2 `itertools` Module

| Function | Purpose |
|---|---|
| `chain(*iterables)` | Flattens multiple iterables into one sequence |
| `count(start, step)` | Infinite counter |
| `cycle(iterable)` | Infinitely repeats a sequence |
| `product(*iterables)` | Cartesian product |
| `permutations(iterable, r)` | All orderings of length r |
| `combinations(iterable, r)` | All unordered selections of length r |
| `groupby(iterable, key)` | Groups consecutive items by key |
| `islice(iterable, stop)` | Slices an iterator lazily |

```python
from itertools import product, combinations, groupby

print(list(product([1,2], ['a','b'])))
# [(1,'a'), (1,'b'), (2,'a'), (2,'b')]

print(list(combinations([1,2,3], 2)))
# [(1,2), (1,3), (2,3)]

data = [1,1,2,2,3]
print([(k, list(g)) for k, g in groupby(data)])
# [(1,[1,1]), (2,[2,2]), (3,[3])]
```
**Trap:** `groupby` only groups **consecutive** matching elements — it does NOT sort first. Ungrouped/unsorted duplicates elsewhere in the list will form separate groups.

### 1.3 `functools` Module (beyond decorators — see Part 3 Ch.3)

```python
from functools import reduce, lru_cache, partial, cmp_to_key

# reduce — cumulative aggregation
print(reduce(lambda acc, x: acc + x, [1,2,3,4], 0))   # 10

# lru_cache — memoization
@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n-1) + fib(n-2)

# partial — pre-fill arguments
double = partial(lambda x, y: x * y, y=2)
print(double(5))   # 10
```
**Interview Q: How does `lru_cache` improve recursive Fibonacci performance?**
**Answer:** "Without caching, recursive Fibonacci recomputes the same subproblems exponentially many times — O(2^n). `lru_cache` stores previously computed results keyed by arguments, so repeated calls with the same input return instantly, dropping it to O(n)."

### 1.4 `operator` Module
```python
from operator import itemgetter, attrgetter, add

people = [{"name": "B", "age": 30}, {"name": "A", "age": 25}]
people.sort(key=itemgetter("age"))
print(people)   # sorted by age
print(add(2, 3))   # 5 — functional form of +
```

### 1.5 `heapq` — Priority Queues
```python
import heapq
nums = [5, 1, 8, 3]
heapq.heapify(nums)
heapq.heappush(nums, 0)
print(heapq.heappop(nums))   # 0 — smallest element, O(log n)
print(heapq.nlargest(2, nums))   # 2 largest, without fully sorting
```
**Interview Q: How would you efficiently find the k smallest elements in a large list?**
**Answer:** "Use `heapq.nsmallest(k, list)`. It's more efficient than sorting the entire list when k is much smaller than n — internally it maintains a heap of size k rather than sorting everything."

### 1.6 `bisect` — Binary Search on Sorted Sequences
```python
import bisect
sorted_list = [1, 3, 4, 7, 9]
pos = bisect.bisect_left(sorted_list, 4)
print(pos)   # 2
bisect.insort(sorted_list, 5)
print(sorted_list)   # [1, 3, 4, 5, 7, 9] — stays sorted
```

### 1.7 `math`, `statistics`, `random`, `decimal`, `fractions`
```python
import math, statistics, random
from decimal import Decimal
from fractions import Fraction

print(math.gcd(12, 18))        # 6
print(math.isclose(0.1+0.2, 0.3))  # True (handles float imprecision)
print(statistics.mean([1,2,3,4]))   # 2.5
print(statistics.median([1,2,3,4])) # 2.5
random.seed(42)                 # reproducible randomness
print(Decimal("0.1") + Decimal("0.2"))  # Decimal('0.3') — exact, unlike float
print(Fraction(1, 3) + Fraction(1, 6))  # Fraction(1, 2)
```
**Interview Trap Q: Why does `0.1 + 0.2 == 0.3` return `False` in Python?**
**Answer:** "Floats are stored in binary floating-point representation (IEEE 754), which can't represent decimals like 0.1 exactly. The tiny rounding error means `0.1 + 0.2` evaluates to `0.30000000000000004`. For exact decimal arithmetic — like money — use the `decimal.Decimal` type instead of `float`."
