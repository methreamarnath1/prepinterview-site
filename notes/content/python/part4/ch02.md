# Chapter 2: System, Files & CLI Tooling

### 2.1 `os` and `sys`
```python
import os, sys

print(os.getcwd())               # current working directory
print(os.listdir("."))           # directory contents
os.makedirs("new_folder", exist_ok=True)
print(os.environ.get("PATH"))    # environment variables

print(sys.argv)        # command-line arguments
print(sys.path)        # module search path
print(sys.exit(0))     # exits the program with status code
```
**Interview Q: What's the difference between `os.getcwd()` and `sys.path`?**
**Answer:** "`os.getcwd()` returns the current working directory of the process. `sys.path` is the list of directories Python searches when importing modules — it includes the script's directory, installed package locations, and any `PYTHONPATH` entries."

### 2.2 `pathlib` — Modern Path Handling
```python
from pathlib import Path

p = Path("data") / "file.txt"    # cross-platform path joining with /
print(p.exists())
print(p.suffix)      # ".txt"
print(p.stem)         # "file"
print(p.parent)       # "data"

for file in Path(".").glob("*.py"):
    print(file)
```
**Why It's Preferred Over `os.path`:** Object-oriented, cross-platform (`/` operator works on Windows and Unix), and chains operations naturally (`p.parent.parent`).

### 2.3 `shutil` — High-Level File Operations
```python
import shutil
shutil.copy("source.txt", "dest.txt")
shutil.move("dest.txt", "archive/dest.txt")
shutil.rmtree("old_folder")   # recursively delete a directory
```

### 2.4 `subprocess` — Running External Commands
```python
import subprocess

result = subprocess.run(["ls", "-l"], capture_output=True, text=True)
print(result.stdout)
print(result.returncode)
```
**Common Mistake:** Using `shell=True` with untrusted input — this is a **security risk** (shell injection), similar to SQL injection. Prefer passing a list of arguments (`["ls", "-l"]`) instead of a shell string when possible.

**Interview Q: What's the security risk of `subprocess.run(cmd, shell=True)`?**
**Answer:** "When `shell=True`, the command string is passed to the system shell for interpretation, meaning any unsanitized user input in that string could inject additional shell commands — a shell injection vulnerability, similar in spirit to SQL injection. It's safer to pass the command and arguments as a list without `shell=True`, since that bypasses shell interpretation entirely."

### 2.5 `argparse` — Building CLI Tools
```python
import argparse

parser = argparse.ArgumentParser(description="A demo CLI tool")
parser.add_argument("filename", help="File to process")
parser.add_argument("--verbose", action="store_true", help="Enable verbose output")
parser.add_argument("--count", type=int, default=1, help="Number of repetitions")

args = parser.parse_args()
print(args.filename, args.verbose, args.count)
```
**Why It's Used:** Automatically generates `--help` text, validates argument types, and handles required vs optional arguments — far more robust than manually parsing `sys.argv`.

### Predict the Output
```python
from pathlib import Path
p = Path("/home/user/docs/report.pdf")
print(p.stem, p.suffix, p.name)
```
**Answer:** `report .pdf report.pdf`
**Explanation:** `.stem` = filename without extension, `.suffix` = the extension, `.name` = the full filename including extension.

### Quick Revision
- `os`/`sys`: process-level info, environment, argv.
- `pathlib.Path`: modern, cross-platform, chainable path handling — prefer over `os.path` in new code.
- `shutil`: high-level copy/move/delete for files and trees.
- `subprocess.run`: preferred way to run external commands; avoid `shell=True` with untrusted input.
- `argparse`: standard way to build CLI tools with auto-generated help.
