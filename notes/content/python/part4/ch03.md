# Chapter 3: Dev-Tool Modules — dataclasses, enum, logging, and more

### 3.1 `dataclasses`

**Definition:** `@dataclass` auto-generates `__init__`, `__repr__`, and `__eq__` for a class based on its declared fields, removing boilerplate.

```python
from dataclasses import dataclass, field

@dataclass
class Point:
    x: int
    y: int
    tags: list = field(default_factory=list)   # avoids mutable default trap

p1 = Point(1, 2)
p2 = Point(1, 2)
print(p1)          # Point(x=1, y=2, tags=[])
print(p1 == p2)     # True — auto-generated __eq__ compares field values
```
**Trap:** Using `tags: list = []` directly (instead of `field(default_factory=list)`) reproduces the classic mutable-default-argument bug — all instances would share the same list.

**`frozen=True`** makes instances immutable (raises on attribute assignment) and automatically hashable.

**Interview Q: What problem do dataclasses solve?**
**Answer:** "Dataclasses eliminate boilerplate when writing classes whose main purpose is holding data. Instead of manually writing `__init__`, `__repr__`, and `__eq__`, you just declare typed fields and the decorator generates them. It's especially useful for simple value objects and configuration classes."

### 3.2 `enum`
```python
from enum import Enum, auto

class Status(Enum):
    PENDING = auto()
    ACTIVE = auto()
    DONE = auto()

print(Status.ACTIVE)          # Status.ACTIVE
print(Status.ACTIVE.name)     # "ACTIVE"
print(Status.ACTIVE.value)    # 2
print(Status.ACTIVE == Status.ACTIVE)  # True — enum members are singletons
```
**Why It's Used:** Prevents "magic strings/numbers" bugs — `Status.ACTIVE` is safer and more self-documenting than a raw string `"active"` scattered through code.

### 3.3 `weakref`, `inspect`, `types`, `abc`

```python
import inspect

def add(a, b=5):
    return a + b

print(inspect.signature(add))    # (a, b=5)
print(inspect.getsource(add))     # prints the source code of add

from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        ...

# Shape()  # TypeError: Can't instantiate abstract class Shape
```
**Interview Q: What's the purpose of `abc.ABC` and `@abstractmethod`?**
**Answer:** "`ABC` marks a class as an abstract base class, and `@abstractmethod` marks methods that subclasses must implement. Trying to instantiate the abstract class directly, or a subclass that hasn't implemented every abstract method, raises a `TypeError`. It's used to enforce a contract/interface across subclasses."

### 3.4 `contextlib`, `importlib`, `pprint`, `textwrap`, `string`, `array`, `queue`

```python
from pprint import pprint
pprint({"a": 1, "b": {"c": 2, "d": [1,2,3]}})   # nicely formatted, indented output

import textwrap
print(textwrap.fill("A very long line of text " * 5, width=40))

from queue import Queue
q = Queue()
q.put(1); q.put(2)
print(q.get())   # 1 — FIFO, thread-safe (unlike plain list)
```
**Interview Q: Why use `queue.Queue` instead of a plain `list` for producer-consumer patterns with threads?**
**Answer:** "`queue.Queue` is thread-safe out of the box — it has internal locking, so multiple threads can safely put and get items without race conditions. A plain list has no such protection and requires manual locking to be used safely across threads."

### 3.5 `logging`
```python
import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s - %(levelname)s - %(message)s")
logger = logging.getLogger(__name__)

logger.debug("Debug message")     # NOT shown — below INFO level
logger.info("Info message")        # shown
logger.warning("Warning message")  # shown
logger.error("Error message")      # shown
```
**Why `logging` over `print()`:** Configurable severity levels, timestamps, output destinations (file, console, network), and per-module control — essential for production code.

### 3.6 `time`, `timeit`, `traceback`, `pdb`, `copy`
```python
import time
start = time.perf_counter()
# work...
print(time.perf_counter() - start)   # perf_counter is preferred for benchmarking (monotonic, high-resolution)

import timeit
print(timeit.timeit("sum(range(100))", number=10000))

import traceback
try:
    1 / 0
except ZeroDivisionError:
    traceback.print_exc()   # prints full stack trace, useful in logging error handlers
```
**`pdb`:** insert `import pdb; pdb.set_trace()` (or `breakpoint()` in Python 3.7+) to drop into an interactive debugger at that line.

### Predict the Output
```python
from dataclasses import dataclass

@dataclass
class Item:
    name: str
    qty: int = 1

a = Item("apple")
b = Item("apple")
print(a == b)
print(a is b)
```
**Answer:**
```
True
False
```
**Explanation:** Dataclass auto-generates `__eq__` comparing field values (`True`), but `a` and `b` are still distinct objects in memory (`is` → `False`).

### Quick Revision
- `@dataclass`: auto `__init__`/`__repr__`/`__eq__`; use `field(default_factory=...)` for mutable defaults.
- `enum.Enum`: named, singleton constants — avoids magic strings.
- `abc.ABC` + `@abstractmethod`: enforce subclass contracts.
- `queue.Queue`: thread-safe FIFO, unlike plain lists.
- `logging` > `print()` for production: levels, formatting, destinations.
- `time.perf_counter()` for benchmarking; `timeit` for micro-benchmarks.
