## 7A. Rapid-Fire Output Questions (30 questions)

For each: predict the output, then check the answer.

**Q1.**
```python
x = [1, 2, 3]
y = x
y.append(4)
print(x)
```
**A:** `[1, 2, 3, 4]` — lists are mutable; `y` and `x` reference the same object.

**Q2.**
```python
def f(a, b=[]):
    b.append(a)
    return b
print(f(1))
print(f(2))
```
**A:** `[1]` then `[1, 2]` — classic mutable default argument trap; the default list persists across calls.

**Q3.**
```python
print(1 == 1.0)
print(1 is 1.0)
```
**A:** `True` then `False` — value-equal but different types/objects.

**Q4.**
```python
a = "hello"
b = "hel" + "lo"
print(a is b)
```
**A:** Often `True` (compile-time constant folding interns both to the same object) — but never rely on this.

**Q5.**
```python
for i in range(3):
    def f():
        return i
    print(f())
```
**A:** `0 1 2` — unlike list-comprehension-lambda closures, here `f` is called immediately each iteration, so `i`'s current value is seen right away, not after the loop ends.

**Q6.**
```python
class A:
    x = 1

class B(A):
    pass

B.x = 2
print(A.x, B.x)
```
**A:** `1 2` — assigning `B.x = 2` creates a new attribute on `B`, it does not mutate `A`.

**Q7.**
```python
try:
    print("try")
    raise ValueError
except ValueError:
    print("except")
finally:
    print("finally")
```
**A:** `try` / `except` / `finally` — `finally` always runs.

**Q8.**
```python
def gen():
    yield 1
    yield 2
g = gen()
print(list(g))
print(list(g))
```
**A:** `[1, 2]` then `[]` — generators are exhausted after one full iteration.

**Q9.**
```python
print(bool([]))
print(bool([0]))
print(bool(0))
print(bool("0"))
```
**A:** `False True False True` — empty containers are falsy; a non-empty container (even holding a falsy value) is truthy; non-empty strings (even "0") are truthy.

**Q10.**
```python
s = {1, 2, 3}
s2 = {1, 2, 3}
print(s == s2, s is s2)
```
**A:** `True False` — value-equal sets, different objects.

**Q11.**
```python
def outer():
    x = 10
    def inner():
        print(x)
        x = 20
    inner()
outer()
```
**A:** `UnboundLocalError` — assigning to `x` anywhere in `inner` makes Python treat `x` as local throughout that function, so the `print(x)` before the assignment refers to an unassigned local variable.

**Q12.**
```python
class Meta(type):
    pass
class Foo(metaclass=Meta):
    pass
print(type(Foo), type(Foo()))
```
**A:** `<class 'Meta'> <class 'Foo'>` — the metaclass creates the class; the class creates instances.

**Q13.**
```python
print([x for x in range(5) if x % 2 == 0])
print((x for x in range(5) if x % 2 == 0))
```
**A:** `[0, 2, 4]` then a generator object repr — list comprehension is eager, generator expression is lazy.

**Q14.**
```python
d = {}
d[1] = "int"
d[1.0] = "float"
print(d)
```
**A:** `{1: 'float'}` — `1 == 1.0` and `hash(1) == hash(1.0)`, so they're the same dictionary key; the second assignment overwrites the first.

**Q15.**
```python
class Base:
    def greet(self):
        return "Base"
class Child(Base):
    def greet(self):
        return super().greet() + " -> Child"
print(Child().greet())
```
**A:** `Base -> Child`

**Q16.**
```python
x = (1)
y = (1,)
print(type(x), type(y))
```
**A:** `<class 'int'> <class 'tuple'>` — parentheses alone don't make a tuple; a trailing comma does.

**Q17.**
```python
print("abc"[::-1])
```
**A:** `cba` — extended slice with step -1 reverses the string.

**Q18.**
```python
def f(*args, **kwargs):
    print(args, kwargs)
f(1, 2, a=3, b=4)
```
**A:** `(1, 2) {'a': 3, 'b': 4}`

**Q19.**
```python
class A:
    def __init__(self):
        self.__x = 1   # name-mangled to _A__x
a = A()
print(a._A__x)
```
**A:** `1` — double-underscore-prefixed attributes are name-mangled, not truly private; still accessible via the mangled name.

**Q20.**
```python
print(sum([], start=[]))
```
Wait — this raises. Let's use a cleaner example:
```python
print(sum([1, 2, 3], 10))
```
**A:** `16` — the second argument to `sum()` is the starting value.

**Q21.**
```python
x = None
print(x or "default")
```
**A:** `default` — `or` returns the first truthy operand, or the last one if none are truthy.

**Q22.**
```python
class Counter:
    count = 0
    def __init__(self):
        Counter.count += 1

Counter(); Counter(); Counter()
print(Counter.count)
```
**A:** `3` — `count` is a class attribute shared across all instances.

**Q23.**
```python
async def f():
    return 5

import asyncio
result = f()
print(type(result))
```
**A:** `<class 'coroutine'>` — calling an async function creates a coroutine object; it must be awaited to actually run.

**Q24.**
```python
print(0.1 + 0.2 == 0.3)
```
**A:** `False` — floating-point representation error.

**Q25.**
```python
lst = [1, 2, 3]
lst2 = lst[:]
lst2.append(4)
print(lst, lst2)
```
**A:** `[1, 2, 3] [1, 2, 3, 4]` — full slice creates a shallow *copy* at the top level, so appending to `lst2` doesn't affect `lst`.

**Q26.**
```python
def f():
    try:
        return 1
    finally:
        return 2
print(f())
```
**A:** `2` — a `return` inside `finally` overrides any earlier `return`.

**Q27.**
```python
class A:
    def __repr__(self):
        return "A()"
print([A(), A()])
```
**A:** `[A(), A()]` — containers display elements using `repr`.

**Q28.**
```python
print(list(zip([1,2,3], ['a','b'])))
```
**A:** `[(1, 'a'), (2, 'b')]` — `zip` stops at the shortest iterable.

**Q29.**
```python
x = 5
def f():
    global x
    x += 1
f()
print(x)
```
**A:** `6` — `global` allows rebinding the module-level name from within the function.

**Q30.**
```python
class Base:
    def __init_subclass__(cls, **kwargs):
        print(f"Subclass created: {cls.__name__}")
        super().__init_subclass__(**kwargs)

class Child(Base):
    pass
```
**A:** `Subclass created: Child` — `__init_subclass__` is a hook that fires automatically whenever a subclass is defined, without needing a metaclass.

## 7B. Interview Traps — Rapid List (25 traps)

1. Mutable default arguments persist across calls.
2. `is` vs `==` — identity vs value; never use `is` for value comparison of ints/strings.
3. Aliasing — `b = a` doesn't copy; both names point to the same mutable object.
4. Shallow copy shares nested mutable objects; only `deepcopy` fully isolates them.
5. Late-binding closures in loops (`lambda: i`) — all capture the same final value.
6. `UnboundLocalError` from assigning to a name anywhere in a function makes it local throughout that function.
7. `global`/`nonlocal` needed to *rebind* (not just read) enclosing-scope variables.
8. Unhashable objects can't be dict keys or set members — defining `__eq__` disables default `__hash__`.
9. Sets and dicts don't preserve insertion order semantics the way you might assume for *iteration guarantees between different runs* — though CPython dicts do preserve insertion order since 3.7 (sets do not guarantee any order).
10. `for...else`: the `else` runs if the loop completes **without** hitting `break`.
11. `finally` always runs, even overriding a `return`/exception from the `try`/`except`.
12. Exception chaining (`raise X from Y`) vs implicit chaining — affects the printed traceback context.
13. Generators are single-use — exhausted after one full iteration.
14. Iterators consumed by one consumer are consumed for all — a shared iterator, once exhausted, is empty everywhere.
15. MRO with multiple inheritance can produce non-obvious method resolution order (C3 linearization) — always check with `Class.__mro__`.
16. `super()` in multiple inheritance follows the MRO, not necessarily the immediate parent.
17. `__new__` returning a non-matching type silently skips `__init__`.
18. `__init__` must return `None` — returning anything else raises `TypeError`.
19. `__str__` falls back to `__repr__`, not the reverse.
20. Descriptors store shared state if you mistakenly store values on `self` inside the descriptor object itself.
21. Metaclasses are inherited by subclasses automatically.
22. Memory management: reference counting is a CPython detail; cyclic references need the GC.
23. GIL prevents true parallel bytecode execution — but is released during I/O, so threading still helps I/O-bound work.
24. Multiprocessing child processes get a **copy** of parent state, not a live shared reference.
25. `asyncio`: forgetting to `await` a coroutine silently does nothing (just a warning) — the code never runs.

## 7C. Comparison Questions (Interview-Style)

**Q: Compare `append()` vs `extend()`.**
**A:** "`append()` adds its single argument as one new element, even if that argument is itself a list. `extend()` iterates over its argument and adds each element individually. So `[1,2].append([3,4])` gives `[1,2,[3,4]]`, while `[1,2].extend([3,4])` gives `[1,2,3,4]`."

**Q: Compare `remove()`, `pop()`, and `del`.**
**A:** "`remove(value)` deletes the first matching *value*, raising `ValueError` if not found. `pop(index)` deletes and returns the element at that *index* (default: last), raising `IndexError` if out of range. `del list[index]` deletes by index too, but doesn't return the value, and can also delete slices or entire variables."

**Q: Compare Iterable vs Iterator.**
**A:** "An iterable is anything with `__iter__`, which returns an iterator. An iterator is an object with both `__iter__` (returning itself) and `__next__` (returning the next value or raising `StopIteration`). All iterators are iterables, but not all iterables are iterators — a list is iterable but is not itself an iterator; calling `iter()` on it produces a separate iterator object."

**Q: Compare Threading vs asyncio for I/O-bound work.**
**A:** "Both help I/O-bound workloads by allowing other work to proceed while one operation waits. Threading uses OS-level preemptive scheduling across multiple threads sharing memory, so race conditions are possible and locks are often needed. asyncio uses a single thread with cooperative scheduling at `await` points, avoiding most race conditions but requiring every I/O operation to be async-aware — a single blocking call can stall the entire event loop. asyncio typically scales better for very high connection counts."

## 7D. Scenario-Based Questions

**Scenario 1:** "You have a function that processes a huge file, line by line, but memory usage keeps growing. What's likely wrong, and how would you fix it?"
**Guideline Answer:** Likely reading the entire file into memory at once (e.g., `.readlines()` or building a list from all lines) instead of iterating lazily. Fix: iterate the file object directly (`for line in f:`), or use a generator to process and yield results incrementally instead of accumulating them all in a list.

**Scenario 2:** "Two threads increment a shared counter, but the final value is sometimes wrong. Why, and how do you fix it?"
**Guideline Answer:** A classic race condition — `counter += 1` isn't atomic. Fix: wrap the increment in a `threading.Lock`, or use `multiprocessing`/atomic primitives if it's actually CPU-bound work being (incorrectly) parallelized with threads.

**Scenario 3:** "Your API client works fine for a few requests but hangs indefinitely under load. What would you check?"
**Guideline Answer:** Check for blocking calls inside `asyncio` coroutines (e.g., a `time.sleep()` or a synchronous `requests.get()` instead of an async HTTP client) stalling the event loop; check for missing timeouts on network calls; check for a connection pool/semaphore limit being exhausted.

## 7E. Mini Mock Interview Transcript

**Interviewer:** What's the difference between a list and a tuple?
**Candidate:** "Lists are mutable, ordered collections — you can add, remove, or change elements after creation. Tuples are immutable — once created, they can't be changed. Because tuples are immutable, they're hashable (as long as their contents are hashable too), so they can be used as dictionary keys or set members, while lists cannot."

**Interviewer:** Can a tuple contain a mutable object?
**Candidate:** "Yes — a tuple being immutable only means you can't reassign what each slot points to. If one of those slots holds a list, you can still mutate that list's contents in place. So `t = ([1,2],)` — `t[0].append(3)` works fine, even though `t` itself never changes structurally."

**Interviewer:** Follow-up — does that make the tuple unhashable?
**Candidate:** "Yes — if a tuple contains a mutable, unhashable element like a list, trying to hash the tuple raises `TypeError`, because hashing recursively requires every element to be hashable."
